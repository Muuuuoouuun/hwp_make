측정일: 2026-07-17

## 측정 범위

- 입력: `data/full_subject_qa/sources`의 2026년 6월 고1 국어·영어·수학·통합사회·통합과학·한국사 문제 PDF
- 문항 인식: PDF를 편집 가능한 문항 모델로 분리하는 `recognize_pdf()` 경로
- 원본 레이아웃 변환: PDF 한 부를 흐름형 HWPX로 직접 만드는 `write_pdf_flow_hwpx()` 경로
- 최종 수치: 개선 후 3회 반복의 중앙값
- 품질 게이트: 실제 문항 수 190개, 원본 52쪽, HWPX 패키지/재열기/첫 페이지 렌더, full-page raster 금지

## 병목 원인과 개선

한국사 2쪽에는 지도·도표에서 유래한 벡터 드로잉 3,682개와 축 정렬 선분 5,433개가 있다. 기존 코드는 표 후보와 박스 후보마다 `page.get_drawings()`를 다시 호출하고, 선분 연결 요소를 반복적으로 묶어 이 한 쪽에 약 144초를 사용했다.

개선 내용:

1. PyMuPDF compact drawing API로 페이지 벡터를 한 번만 읽는다.
2. 흐름 레이아웃에 필요한 사각형과 긴 가로·세로선만 캐시한다.
3. 1,200개를 넘는 축 정렬 선분은 지도·벡터 삽화로 분류해 O(n²) 표/박스 연결 요소 분석을 생략한다.
4. 실제 자료 박스는 상·하단 가로선과 같은 구간을 닫는 좌·우 세로선을 매칭해 선형에 가까운 비용으로 복원한다.
5. `<보기>`처럼 라벨이 상단 테두리를 끊는 경우 좌우 선분을 가상 테두리로 합쳐 박스를 유지한다.
6. PDF 텍스트 딕셔너리와 줄 목록도 페이지당 한 번만 만들고 이미지/표/본문 분석이 공유한다.
7. 변환 통계에 페이지별 시간, 최장 페이지, 벡터·축선 수, 밀집 벡터 페이지 수를 노출한다.
