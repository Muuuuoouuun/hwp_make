# 프리미엄 스튜디오 1차 구현

2026-09-07 · `codex/premium-reorder-numbering`

## 사용 방법

기존처럼 `./run_local.ps1`로 실행한다. `/`, `/premium`, `/premium/studio` 모두 파일 입력만 있는 간단한 화면으로 시작한다. 파일 인식이 끝나면 문항 수와 변환·편집 동작을 보여 준다. 로그인한 상태에서 ‘문항 편집’을 눌러야 확장 편집기로 전환한다. 로그인만으로 편집기를 열지 않는다.

이 버전은 **로컬 내부 미리보기**다. 단일 소유자의 로컬 계정 생성·로그인·로그아웃을 구현했다. 비밀번호는 PBKDF2로 저장하고 HttpOnly 세션 쿠키로 인증한다. 프리미엄 미리보기·내보내기는 서버에서 세션과 동일 출처를 검사한다. 유료 결제·구독 이용권·웹 사용자별 자료 격리는 구현하지 않았다. `workspace: premium` 필드만으로 접근 권한이 생기지는 않는다.

## 구현된 동작

- 모든 경로에서 URL이나 저장된 화면 모드 때문에 스튜디오로 자동 전환되지 않는다. 첫 화면은 로고·로그인·파일 입력으로 제한하며, 변환 버튼·결과·도움말은 입력 후 필요한 단계에서 표시한다.
- 실제 `/api/import` 응답으로 인식 결과를 표시한다. 로그인 중 선택 파일과 인식 문항을 유지하고, 편집 진입 시 같은 파일을 다시 가져오지 않는다. 인식 실패·0문항에서는 편집기를 열지 않는다. PDF는 기본 변환과 재시도를 제공한다.
- 가져오기 응답의 `ordered_ids`로 기존 문항과 새 문항이 섞인 파일도 원래 순서를 유지한다. 파일 교체·삭제 중 도착한 이전 응답은 무시하며 불완전한 순서 응답으로 편집기를 열지 않는다.
- 프리미엄 화면에서 기존 문항 이동 기능과 연속 번호·시작 번호(마지막 번호 포함 1~999)·원번호 유지 옵션을 제공한다. 목록·순서 편집 모달에 출력 번호와 원번호를 구분한다.
- 순서·번호 정책은 로컬 브라우저에 저장한다. 이전 작업은 로그인한 계정 메뉴에서 명시적으로 재개한다. 로그아웃하면 파일·편집 상태를 비우고 입력 화면으로 돌아간다. 이름 있는 여러 시험지의 서버 저장·복제는 아직 없다.
- `/api/export`와 `/api/preview`는 프리미엄 요청에서 같은 `prepare_export_problems` 함수를 사용한다. 원본을 복사한 뒤 출력 번호를 본문·정답표·해설에 함께 전달한다. 기본 요청은 이전 방식대로 원번호를 유지한다.
- 인식된 원번호 접두사만 정리하며, 준비된 본문을 writer가 다시 정리하지 않아 `1.5` 같은 소수가 잘리는 것을 막는다.
- 원번호 공백·중복, 번호 범위, 미지원 지문·이미지·원본 배치 입력을 검수한다. 중복 원번호는 명시적으로 확인해야 하고 문항 저장·이동으로 대상이 바뀌면 다시 확인한다.
- 편집 가능한 일반 PDF 문항의 좌표는 출처 정보로 허용한다. 원본 배치 보존·이미지 대체·공유 지문 경로는 별도로 거절한다. 자유 텍스트의 다른 문항 번호 참조는 자동 치환하지 않는다.

번호 변경은 문제은행 원본에 저장하지 않는다. 기존 문항 편집기의 본문·원번호 직접 저장 기능은 여전히 문제은행을 수정한다. 시험지별 내용 스냅샷 편집과 서버 revision 관리까지 구현한 것으로 해석하지 않는다.

| 실제 브라우저 | 이전 번호 편집 구현에서 시작 21·이동·모바일 모달·결과 번호를 확인했다. 이번 단계에서는 프리미엄 URL 직접 접속과 로그인 전후에 입력만 표시되는 것을 확인했다. 파일 선택 도구가 파일 선택 이벤트를 받지 못해 실제 파일 업로드부터 이어지는 전체 브라우저 검증은 완료하지 못했다. 해당 상태 전환은 별도 런타임 검사로 검증했다. |
| HWPX 렌더 미리보기 | 테스트 문항 원본 27·12가 출력 21·22로 표시되고 빠른 정답과 해설도 동일 번호인 것을 시각 확인 |

브라우저 검증은 TEMP 디렉터리의 별도 DB와 합성 문항으로 실행했다. 실제 한글·Word에서 편집/저장, 유료 웹 계정·결제, 실물 스캔 재번호, 공유 지문 그룹 편집은 검증 대상 밖이다. rhwp의 기존 manifest fallback 경고는 출력됐으나 관련 검사는 통과했다.

최종 기본 화면은 1280×720 및 390×844에서 확인했으며 콘솔 오류·경고는 없었다. 계정 메뉴에서 명시적인 이전 작업 재개와 로그아웃 후 입력 화면 복귀도 확인했다. 통합 러너는 `verify_*.js` 전체를 찾아 새 프리미엄·단계 전환 검사까지 포함한다. 이번 변경에서 전체 통합 러너를 실행한 것은 아니며 관련 검사를 개별 실행했다.
