# 본부 판정 — D1 조사 제안의 수용·기각

판정 원칙: 다수결이 아니라 근거. '확인'은 본부가 코드 원문을 읽거나 실물·합성 PDF로 재현한 것, '보고'는 CLI·에이전트 보고만 있는 것.

## 수용해 구현한 것

| # | 제안(출처) | 본부 확인 방법 | 결과 |
|---|---|---|---|
| 1 | 테두리 상자 안 글 소실 (Codex 1, Grok 19·P3) | 고아 줄 측정(90책자) + 생활과 윤리 1~3번 실물 대조 + 가져오기 최종 결과 확인 | **확인.** 본문의 31.8%가 소실. 수정 후 0.13% |
| 2 | 국어 등 같은 쪽 공통 지문 미연결 (Codex 8, Grok 1·P2) | 고아 줄 측정 + 국어 실물(112문항 중 지문 붙은 문항 0 → 106) | **확인.** 문항 박스 밖 7.9% → 0.17% |
| 3 | 한쪽 단에만 문항이 있는 쪽의 1단 오판 (Grok 7) | 국어 문항 쪽 157개 중 48개 해당, 반대편 글 58,934자가 문항에 섞임을 집계 | **확인.** 중앙 구분선 근거로 2단 판정 |
| 4 | 쪽을 넘은 지문 뒷부분 소실 (Grok 3·4·5 계열) | 고아 줄 위치 분류(쪽 선두 16,046자) | **확인.** 열린 지문에 이어 붙임 |
| 5 | 번호 줄 120자 잘림 (Codex 3) | 코드 원문(`text[:120]`이 TITLE 본문으로 쓰임) + 합성 PDF | **확인.** 줄 전체 사용 |
| 6 | 본문의 오전·오후 문항 줄이 날짜로 버려짐 (Grok 22·P7) | 코드 원문 + 합성 PDF | **확인.** 쪽 여백 8% 밴드로 제한 |
| 7 | 번호 0 폴백 문항이 변환 전체를 실패시킴 (Claude C1) | 합성 PDF 2종(표지 쪽, 중간 여백 쪽)으로 ValueError 재현 | **확인.** 인벤토리에서 제외, 변환 성공 |
| 8 | 변환 한 번에 인식 2회 (Claude I1, M2·M3) | 호출 지점 두 곳 직접 읽음 + 회귀 검사로 1회 고정 | **확인.** 결과를 넘겨 1회로 |
| 9 | 편집형 경로가 인식의 래스터·PNG를 버림 (Claude I2) | 코드 원문(작성기는 쪽·번호만 사용) | **확인.** `render=False` |
| 10 | 수식 AI 체크박스가 AI를 부르지 않음 (M3) | 구 경로 10207~10778줄에 수식 AI 참조 0건 + A/B 실행(네트워크 시도 0회, 지표 하락) | **확인.** 네이티브 경로로 통일, 요청 시 안내 |
| 11 | 배경 표 후보마다 전 쪽 도형 재추출 (M2 후보 4) | M2 호출 수(국어 518회) | **보고.** 쪽 메모 적용, 효과는 재측정으로 확인 |
| 12 | 검수 단계를 끌 수 없음 (M3 8, M2) | M2: 작성 뒤 단계가 58~75%, 산출 해시 동일 | **보고+확인.** `quality_check="fast"` 추가 |

본부가 구현 중 추가로 찾은 것: 1~5번 문항의 번호 줄이 숫자형 선지로 오인되어 문항 박스가 일찍 잘리는 버그(`_refine_problem_bottom`). 새 회귀 검사의 표 케이스가 드러냈고 함께 고쳤다.

| 3단 배치, 비대칭 2단, 전각 번호, 100번 이상 (Codex 6·7·10, Grok 6·8~11) | 코퍼스에 사례가 없어 측정 근거 없이 규칙을 넣게 된다. 탐지 신호부터 넣는 것이 맞다 |
| 문항 단위 인벤토리 JSON, 신뢰도 필드 전달 (Claude I4·I5) | 기능 추가. 이번 범위(결함 수정) 밖 |
| 인접 문항 줄 중복 소유 (Codex 2), 그림 병합 순서 의존 (Codex 14), 문자 좌표 선생성 (Codex 15) | 발생 조건이 드물거나 이득이 미확인 |

# D4 교차 평가 판정

점수: Codex 정확성 감사 76 · Claude 하류 영향 62 · Grok 반례 62 · Antigravity 손잡이 설계 82.

## 수용해 반영한 것

| 지적(출처) | 본부 확인 | 처리 |
|---|---|---|
| 연결할 문항이 없는 지문의 본문 소실 (Codex 1) | 코드 경로 확인 + 합성 PDF | 같은 쪽 앞 문항에 되돌림 |
| 중앙 세로선이 있는 1단 시험지를 2단으로 오판 (Codex 2, Grok 1) | 방어 조건을 넣어도 국어 48쪽은 0쪽 탈락함을 집계 | 본문이 가운데를 가로지르면 1단 유지 |
| 머리글 밴드 안의 첫 문항을 지나쳐 문항 본문이 지문에 섞임 (Codex 4, Grok 3) | 번호 줄 2,577개 중 7개가 13% 밴드 안. 줄 위치 분포에서 머리글(8~10.5%)과 본문(11.8%~) 사이 빈 구간 확인 | 번호 줄 확인을 먼저, 수집 경계 11% |
| 번호 재시작 뒤 다음 유형으로 지문이 넘어감 (Codex 5) | 코드 경로 + 합성 PDF | 번호가 같거나 줄면 중단 |
| 한 경로로 그린 표를 놓침 (Codex 7) | 합성 PDF로 재현 | 경로 안 선분을 그림 판정에 사용 |
| 8% 밖 인쇄일이 문항이 됨 (Codex 8) / 날짜로 시작하는 문항 줄이 버려짐 (Grok 6) | 서로 반대 방향의 지적. 합성 PDF 두 경우 모두 재현 | 줄 전체가 날짜·시각뿐일 때만 어디서든 인쇄일. 느슨한 판정은 여백에서만 |
| 전각 대괄호 지문 머리 (Codex 9, Grok 5 일부) | 합성 PDF | 인식 정규식 두 곳 확장 |
| 빠른 검수의 미측정을 실패로 기록 (Codex 10) | 코드 경로 | None(미측정)으로 |
| 상자 글이 선지로 오인됨 (Claude 1) | 수능 36책자 가져오기 전후 비교: 선지 6개 이상 4건 → 33건(제2외국어 30건) | 원문자 선지가 있으면 글자 라벨 줄은 보기 항목. 33건 → 3건(기준선보다 적음) |
| 지문 사본으로 저장량이 부풂 (Claude 3a) | 레이아웃 저장량 41.9MB → 77.1MB 실측 | 지문 줄은 글·상자·쪽만 저장. 55.0MB(국어 5.3MB, 기준선 5.7MB) |
| 지문 줄에 쪽 구분이 없음 (Claude 5) | 코드 경로 | 줄마다 `page` 기록(화면 필터는 다음 단계) |

# D5 최종 감사 판정

Codex 3단계 최종 감사: 74점, "배포 보류". 지적 8건 중 7건을 반영했고, 반영 뒤 회귀 검사는 40항목이다.

| 지적 | 본부 확인 | 처리 |
|---|---|---|
| 1. 빈 줄이나 원문자 한 개가 A.~E. 선지를 없앤다 (치명) | 코드 원문: `"" in 문자열`이 참. 본부가 D4 반영 중에 만든 회귀 | 원문자가 3개 이상일 때만 글자 라벨 줄을 보기 항목으로 본다. 빈 줄·혼합 라벨 검사 추가 |
| 2. 번호 재시작 방어가 지문의 첫 연결에는 없다 (치명) | 합성 PDF(홀수형 발췌 + 짝수형)로 재현 | 열린 지문은 읽기 순서상 바로 다음 문항이 시작 번호일 때만 연결. 같은 쪽 지문은 같은 쪽에서만 찾는다 |
| 3. 범위 머리가 있으면 1단 보호 조건이 무력해진다 (치명) | 합성 PDF로 재현 | 영어는 범위 머리 조건, 그 밖은 "가운데를 가로지르는 줄 없음" 조건으로 분리 |
| 4. 미연결 지문을 되돌리면 앞 문항의 선지가 바뀔 수 있다 (중요) | 코드 경로 | **보류.** 발췌본에서 받을 문항이 없는 지문에 원문자 줄이 있는 경우로 한정. 독립 지문 항목 저장은 기능 추가 |
| 5. 머리글 필터가 확정된 번호 줄을 지문 경계에서 지운다 (중요) | 합성 PDF로 재현 | 확정된 번호 줄은 필터에서 유지 |
| 6. 한 경로의 사선 테두리가 본문 상자를 이미지로 만든다 (중요) | 합성 PDF로 재현 | 경로에서 꺼내는 선분은 세로선만 |
| 7. 영어 판정 입력의 줄 순서가 바뀌었다 (중요) | 96책자 결과는 같았으나 순서 차이는 사실 | PDF 추출 순서를 보존해 이전과 같은 순서로 판정. 96책자 재대조 동일 |
| 8. 전각 지문 머리의 번호 재부여 거절 (사소) | 코드 경로 | `exam_numbering._SHARED_HEADING`에 전각 괄호 추가 |

교훈: 본부가 교차 평가를 반영하면서 넣은 한 줄(`other.lstrip()[:1] in CIRCLED_CHOICE_MARKERS`)이 공용 가져오기 함수의 회귀였다. 반영분도 다시 감사받아야 한다.
