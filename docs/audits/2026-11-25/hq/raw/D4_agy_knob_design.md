# D4 Antigravity — 속도-품질 손잡이 설계 평가 보고서

**설계 점수:** **82점 / 100점**

### 총평
백엔드에 추가된 `quality_check="fast"`의 분기 위치([main.py#L1140-L1145](<repo>/app/main.py#L1140-L1145))는 **엔지니어링 관점에서 대단히 훌륭한 최적화(A+)**입니다. HWPX 산출물 바이너리를 변경하지 않으면서 수학 40쪽 기준 실행 시간의 **59%(30.7초 절감)**, 국어 40쪽 기준 **38%(36.1초 절감)**를 즉시 제거하고, 교사에게 필수적인 "확인 필요 문항 N개" 검수는 온전히 보존합니다.
그러나 **화면(UI/UX) 설계 점수는 60점 수준**에 머물러 있습니다. 핵심 속도 조절 손잡이(`quality_check`, `max_pages`, `variant_policy`)는 화면에 일체 노출되지 않은 반면([index.html#L57-L85](<repo>/static/index.html#L57-L85)), 화면에 유일하게 존재하는 손잡이인 "Gemini 수식 인식" 체크박스는 백엔드에서 실제 AI를 호출하지 않는 무작동 더미로 방치되어 교사에게 혼란과 불신을 야기하고 있습니다.
따라서 **1) 무작동 AI 체크박스 즉시 제거**, **2) 기본 변환을 `fast`로 전환하여 Time-to-File(파일 획득 시간)을 20초대로 단축**, **3) 사후 "정밀 대조 실행" 버튼 분리**를 적용하면 완성도 95점 이상의 프로덕션 UX를 확보할 수 있습니다.

## 1. `quality_check` 설계 평가

### (1) 자르는 위치의 적절성: **매우 적절함 (적중도 100%)**
- **근거 수치 분석 (본부 실측값 기준)**:
  - **수학 40쪽 (총 52초)**: 원본 대조 렌더가 **59% (30.68초)**를 점유. 이를 생략하면 **~21.3초** 만에 완료되어 변환 속도가 **2.4배 향상**됩니다.
  - **국어 40쪽 (총 95초)**: 원본 대조 렌더가 **38% (36.1초)**를 점유. 이를 생략하면 **~58.9초**로 단축되어 브라우저 타임아웃/이탈 체감 구간(1분 이상)을 크게 줄입니다.
  - **지구과학 4쪽 (총 12.5초)**: 원본 대조 렌더 31% (3.88초) 생략 시 **~8.6초**로 단축됩니다.
- **산출물 무결성**:
  - HWPX 파일 작성은 앞선 작성 단계([main.py#L1082-L1090](<repo>/app/main.py#L1082-L1090))에서 이미 완결되며, 검수·대조 단계는 파일 내용(해시)을 단 1바이트도 수정하지 않습니다.
- **핵심 정보 보존**:
  - `fast`가 생략하는 것은 쪽당 0.7~1.1초가 소요되는 전면 픽셀 대조([main.py#L1145](<repo>/app/main.py#L1145))뿐입니다.
  - 문항별 결함 탐지(`inspect_pdf_editability`, `inspect_question_rendering`, `build_export_review` — [main.py#L1120-L1158](<repo>/app/main.py#L1120-L1158))는 `fast` 모드에서도 그대로 실행됩니다.
  - 따라서 교사에게 가장 행동 지향적인 피드백인 **"확인 필요 문항 N개" 목록([app.js#L3868-L3875](<repo>/static/app.js#L3868-L3875))은 온전히 제공**되며, 생략되는 것은 모호한 합성 점수인 "자동 점검 N점"과 시각 일치율뿐입니다. 자르는 위치는 기술적·실용적으로 완벽합니다.

### (2) 기본값은 무엇이어야 하는가: **`fast`(빠른 변환)가 기본이어야 함**
- **근거 및 타당성**:
  1. **교사의 이용 행태**: 변환 화면을 쓰는 교사의 1차 목적은 "지금 당장 수업/인쇄에 쓸 HWPX 파일 다운로드"입니다. 웹 UI에서 50초~90초 대기는 브라우저 새로고침이나 탭 닫기를 유발하는 '위험 구간'이지만, 20초대는 사용자가 화면을 지켜볼 수 있는 '안정 구간'입니다.
  2. **가치 동일성**: `full`과 `fast`의 생성 파일 해시가 100% 동일하므로, 기본값을 `fast`로 설정해도 교사가 받는 학습지/시험지의 완성도에는 손실이 전혀 없습니다.
  3. **검수 채널의 주객전도 방지**: 교사는 시스템이 매긴 '자동 점검 점수'보다 자신이 직접 한글(HWP) 프로그램에서 열어 수식과 배치를 눈으로 확인하는 것을 신뢰합니다. 30여 초의 렌더링 비용을 기본값으로 강제할 이유가 없습니다.

### (3) 교사 대상 용어 3안
1. **1안 (직관적 설명형, 권장)**: **"원본 화면 대조 (정밀 점검)"**
   - 체크박스/토글 부제: *"변환 후 원본 PDF와 1:1 화면 대조를 수행합니다 (약 30초 추가 소요)"*
2. **2안 (속도 대비 모드형)**: **"빠른 변환" vs "정밀 대조 변환"**
   - 버튼/옵션 라벨: *"빠른 변환 (권장 · 약 20초)"*, *"정밀 검증 (화면 대조 포함 · 약 50초)"*
3. **3안 (결과 중심형)**: **"자동 점검 점수 측정 포함"**
   - 설명: *"HWPX 파일 생성은 동일하며, 원본 일치 점수 산출 및 화면 대조를 함께 실행합니다."*

## 2. 화면 노출 구성안 2가지 및 사후 점검 타당성

### 구성안 A: 변환 전 선택형 (Pre-conversion Toggle)
- **화면 구조**:
  - `static/index.html` [index.html#L57-L60](<repo>/static/index.html#L57-L60)의 수식 AI 체크박스 자리에 배치.
  - 형태: `[ ] 원본 화면 대조 포함 (점수 측정 · 약 30초 추가 소요)` (기본값: 해제).
- **장점**:
  - 구현이 극히 단순함. `static/app.js` [app.js#L2767-L2774](<repo>/static/app.js#L2767-L2774)에서 `quality_check: checked ? "full" : "fast"`로 전달하기만 하면 됨.
  - 변환 시작 전에 처리 방식을 교사가 명시적으로 확정함.
- **단점**:
  - 교사에게 사전 인지 부하를 줌 ("화면 대조를 안 켜면 HWPX 품질이 떨어지는 것 아닌가?"라는 불필요한 의구심 유발).
  - 이미 느린 모드로 실행을 시작하면 도중에 취소하고 빠른 모드로 바꿀 수 없음.

### 구성안 B: 변환 우선 완료 후 사후 정밀 점검 분리형 (Post-run Verification, 권장)
- **화면 구조**:
  - 변환 실행 시 무조건 `quality_check="fast"`로 구동하여 **20~50초 만에 HWPX 즉시 다운로드 제공**.
  - 변환 완료 카드([app.js#L4037-L4069](<repo>/static/app.js#L4037-L4069)) 하단에 보조 액션 버튼 노출:
    - `[🔍 원본과 화면 정밀 대조 실행 (자동 점검 점수 확인)]`
  - 교사가 버튼을 누르면 백그라운드로 대조 렌더를 수행하고, 완료 시 "시각 일치 미검증" 안내([app.js#L3889](<repo>/static/app.js#L3889))를 "자동 점검 96.2점 / 시각 일치율 98.4%"로 갱신.
- **장점**:
  - **Time-to-File(체감 대기 시간) 최소화**: 수학 기준 21초 만에 파일을 받고 한글에서 편집을 시작할 수 있음.
  - 심리적 안정감: 교사는 파일을 이미 확보한 상태이므로, 대조 검사가 30초 걸려도 체감 대기 시간은 0초에 수렴함.
- **단점**:
  - 백엔드에 기존 run_dir의 파일을 대상으로 fidelity 검사만 사후 수행하는 엔드포인트(예: `POST /api/pdf-layout-export/{run_id}/verify`) 추가 개발 필요.

### 변환 후 점검 분리 방식의 타당성 평가
- **기술적 타당성: 극상 (A+)**
  - 백엔드 변환 시 세션 디렉터리(`run_dir`)에 원본 PDF 사본(`source_copy`)과 산출 HWPX(`output_path`)가 이미 물리 파일로 저장되어 있습니다([main.py#L1068-L1074](<repo>/app/main.py#L1068-L1074)).
  - 대조 렌더 함수 `_pdf_export_fidelity`([main.py#L1145](<repo>/app/main.py#L1145))는 이 두 파일 경로와 `render_dir`만 넘겨주면 언제든 완전히 독립적으로 재실행 가능한 순수 함수형 구조입니다.
- **사용자 경험 타당성: 극상 (A+)**
  - 파일 생성과 사후 검증의 비동기 분리는 웹 서비스 최적화의 표준 패턴이며 교사의 실제 편집 흐름과 정확히 일치합니다.

## 4. 수식 AI 체크박스 처리 방안

### 권고: **즉시 화면에서 숨김(제거)** ([index.html#L57-L60](<repo>/static/index.html#L57-L60))

### 근거:
1. **제품 신뢰도 훼손 방지 (핵심)**:
   - 현재 화면의 `<input id="simpleMathAi">`는 백엔드 `write_pdf_structured_hwpx`([main.py#L1086](<repo>/app/main.py#L1086))로 파라미터를 넘기지만 실제 Gemini API를 호출하지 않는 no-op 상태입니다.
   - 교사가 API 키를 설정하고 체크박스를 켰음에도 결과와 속도에 아무 변화가 없다면, 사용자는 제품 전체의 기능 작동 여부를 불신하게 됩니다.
2. **속도 정책과의 근본적 충돌**:
   - 만약 이를 실제로 Gemini Vision 멀티모달 API에 연결할 경우, 40쪽 수학 시험지의 수십~수백 개 수식 영역을 외부 API로 왕복 호출하게 됩니다.
   - 이는 변환 시간을 최소 30초~2분 이상 가산시키며, API 할당량(Quota) 초과 및 네트워크 단절 에러를 유발하여 "간단 변환"의 존재 목적(빠르고 안정적인 변환)을 완전히 파괴합니다.
3. **간단 화면의 원칙(단순성) 회복**:
   - 간단 변환 화면은 비전문가 교사가 파일만 올리고 1클릭으로 변환하는 공간입니다. 작동하지 않는 AI 옵션을 제거해야 새로 추가될 `quality_check`(빠른 변환) 손잡이가 직관적으로 교사에게 전달됩니다. (AI 관련 설정은 프리미엄 스튜디오 설정 모달로 완전 격리하는 것이 타당합니다.)
