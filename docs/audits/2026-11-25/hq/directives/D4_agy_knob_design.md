# D4 Antigravity — 속도-품질 손잡이 설계 평가

## 역할
교사가 쓰는 변환 화면의 관점에서 속도-품질 조절 방식을 평가하고 구성안을 내는 설계자.

## 본부가 잰 값(이 PC, 편집형 PDF 변환 한 번)
| 책자 | 총 시간 | 인식 | 작성 | 검수(편집성+문항 렌더) | 원본 대조 렌더 |
|---|---|---|---|---|---|
| 국어 40쪽 | 95초 | 4% | 33% | 18% (+재인식 4%) | 38% |
| 수학 40쪽 | 52초 | 4% | 21% | 10% (+재인식 4%) | 59% |
| 지구과학 4쪽 | 12.5초 | 8% | 34% | 17% (+재인식 8%) | 31% |

- 작성 뒤 단계(검수·대조)는 산출 HWPX를 바꾸지 않는다(파일 해시 동일). 사용자에게 주는 것은 "확인 필요 문항 N개"와 "자동 점검 N점"뿐이다.
- 원본 대조는 쪽마다 렌더 0.7~1.1초가 고정으로 든다.
- 홀·짝형 합본 책자는 `variant_policy="first"`로 앞 형만 변환하면 절반 시간이다(범위를 줄이는 것).
- `max_pages`는 API에만 있고 화면에 없다.

## 이번에 넣은 것
API 옵션 `quality_check`: `"full"`(기본) / `"fast"`. fast는 원본 대조 렌더만 생략한다. 결과 파일과 문항별 검수 표시는 같고, 점수 대신 "시각 일치 미검증"과 "빠른 변환: 원본과의 화면 대조를 생략했습니다" 안내가 나온다. 화면에는 아직 노출하지 않았다.

## 화면 현황(코드 확인용, 읽을 수 있으면 읽는다)
- 간단 변환: `<repo>\static\index.html` 50~70줄, `static\app.js`의 `runSimpleConversion`·`simpleQualityMessages`.
- 간단 변환 화면의 선택지는 지금 "Gemini 수식 인식" 체크박스 하나다(이 체크박스는 실제로는 AI를 부르지 않는다는 것이 이번에 확인됐다).

## 할 일
1. `quality_check` 설계 평가: 자르는 위치가 맞는가, 기본값은 무엇이어야 하는가, 교사에게 어떤 말로 보여야 하는가(용어 3안).
2. 화면 노출 구성안 2가지(예: 체크박스 / 변환 후 "정밀 점검 실행" 버튼으로 분리)와 각 장단점. 변환을 먼저 끝내고 점검을 나중에 따로 돌리는 방식의 타당성.
3. 그 밖의 손잡이 후보(앞 형만, 쪽 범위 미리보기, 문항 렌더 검사 생략)를 "품질 손실 없음 / 범위 축소 / 품질 저하"로 분류한 표.
4. 수식 AI 체크박스를 어떻게 처리해야 하는가(숨김, 문구 변경, 실제 연결) — 근거와 함께.
5. 교사용 안내 문구 초안(진행 중, 완료, 빠른 변환 완료 각각 한 줄).

## 출력
맨 위에 현재 설계 점수(100점)와 총평. 근거는 위 수치나 `파일:줄`. 추측은 '추정'으로 표시.
