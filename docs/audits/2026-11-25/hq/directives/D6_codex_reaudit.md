## 본부 처리
| D5 지적 | 처리 |
|---|---|
| 1. 빈 줄·원문자 한 개가 글자 선지를 없앰 | `importers._choice_line_body`: 본문 전체의 원문자 개수가 3개 이상일 때만 글자 라벨 줄을 보기 항목으로 본다 |
| 2. 지문의 첫 연결에 유형 경계 검증 없음 | `pipeline.py` 지문 연결: 열린 지문(`open`)은 뒤 쪽의 첫 번호 문항이 시작 번호일 때만, 그 밖은 같은 쪽의 시작 번호 문항만. 문항 없는 지문 쪽도 `open`으로 표시 |
| 3. 범위 머리가 1단 보호를 무력화 | `pdf_segment.py` 단 판정: 영어는 `bool(range_sides)`, 그 밖은 `not crosses_middle` |
| 4. 미연결 지문 복구가 앞 문항 선지를 바꿈 | 보류 |
| 5. 머리글 필터가 확정된 번호 줄을 지움 | `_shared_passage_regions`: 확정된 번호 줄은 필터에서 유지 |
| 6. 사선 테두리가 본문 상자를 이미지로 | 경로에서 꺼내는 선분은 세로선(`abs(dx) <= 1`)만 |
| 7. 영어 판정 입력 순서 | `source_order`를 줄에 기록하고 `top_quarter_lines`를 추출 순서로 |
| 8. 전각 지문 머리의 번호 재부여 | `exam_numbering._SHARED_HEADING`에 전각 괄호 |

## 찾을 것
1. 위 처리가 **틀리게 구현된 곳**.
2. 처리 2가 만든 새 회귀: 영어(같은 쪽 지문, 두 단에 걸친 지문, 쪽 끝에서 시작해 다음 쪽 문항으로 이어지는 지문, 홀·짝형 합본)에서 이전에는 연결되던 지문이 연결되지 않게 되는 경우. `passage.get("open")`이 영어의 `_shared_passage_regions` 결과에도 붙는지, 문항이 뒤쪽 **같은 쪽 다른 단**에 있는 지문이 `open`으로 잘못 분류되는지.
3. 처리 1의 기준(원문자 3개 이상)이 깨는 흔한 입력.
