# D1 Grok — 인식 실패 모드 예측

## 역할
한국 시험지 PDF의 실제 다양성을 아는 반대 심문자. 아래 알고리즘이 어떤 시험지에서 깨질지 예측한다. 코드를 직접 읽을 수 있으면 `app/recognition/pdf_segment.py`를 읽고, 못 읽으면 아래 발췌만으로 답한다(읽었는지 여부를 첫 줄에 적는다).

## 알고리즘 발췌(pdf_segment.py)
```python
_MARKER_RE = re.compile(r"^([1-9][0-9]?)([.)])(?:\s|$)")          # 문항 번호: 줄 맨 앞 "12." / "3)"
_NUMERIC_CHOICE_MARKER_RE = re.compile(r"^\s*([1-5])([.)])(?:\s|$)")  # 숫자형 선지 "1)"~"5)"
_PASSAGE_RANGE_RE = re.compile(r"\[\s*(\d{1,2})\s*[~～∼\-–]\s*(\d{1,2})\s*\]")  # [13~14] 묶음
_HEADER_TOKENS = ("年", "월", "교시", "점]", "학년도", "모의평가")   # 상단 밴드 배제 토큰
_CHOICE_MARKERS = ("①".."⑤", "❶".."❺", "➀".."➄")

# 선지형 마커 억제(_filter_choice_like_markers)
lane_tolerance = max(42.0, width_px * 0.035)   # 같은 차선으로 보는 x 허용폭
choice_gap     = max(80.0, height_px * 0.075)  # 직전 문항/선지 아래 이 거리 안이면 선지 후보
choice_run_gap = max(70.0, height_px * 0.045)  # 1→2→3 연속 탐색 간격
# 규칙: 숫자형(1~5)이고 같은 차선의 직전 문항이 있을 때
#   (a) 기대 다음 선지 번호와 같고 가까우면 억제
#   (b) 가깝고 번호 <= 직전 문항 번호면 억제
#   (c) 번호 1이고 <= 직전 문항 번호이며 앞으로 1,2,3 연속이 보이면 억제
```
이후 단계: 마커 center-x 클러스터로 1단/2단 판정 → 컬럼 안에서 마커 top부터 다음 마커 top까지를 문항 박스로 → 마지막 ①~⑤ 선지 줄까지 하단 다듬기 → 그림 bbox 재부착. 수식 글리프가 사설 영역(PUA) 12% 이상이면 텍스트 불신.

## 할 일
시험지 유형별로 실패 모드 25~30가지를 예측한다. 다룰 유형: 평가원·교육청 모의고사, 사설 모의고사, 학교 내신(한글로 만든 뒤 PDF), 과목별(국어 긴 지문과 묶음 문항, 수학 단답형·서답형, 영어 듣기와 장문, 탐구 자료 박스와 ㄱㄴㄷ 보기, 한문 세로쓰기, 제2외국어 문자), 1단·2단·3단, 번호 형식 변종("1번", "문 1.", "[1]", "1 ." , "01.", "서답형 1.", "【1】"), 100번 이상 문항, 소문항 (1)(2), 배점 표기 "[3점]", 쪽 넘김 문항.

## 출력 형식(실패 모드마다)
- 유형과 구체 배치(한 줄)
- 어느 규칙이 왜 깨지는가(위 발췌의 이름으로)
- 결과: 누락 / 과분할 / 병합 / 순서 뒤바뀜
- 코드에서 잡을 수 있는 탐지 신호(예: 번호 시퀀스 결손, 차선 수 3 이상)
- 발생 빈도 추정(높음/중간/낮음)과 근거

마지막에 "가장 싼 방어 5가지"(규칙 수정이 아니라 결과 검증으로 잡는 방법 우선)를 적는다. 근거 URL은 필요 없다.
