# 모의고사 한글 파일: 웹 조사·실물 분석·앱 동작 검증

조사일: 2026-09-21. **웹 조사와 파일·가져오기 실험은 실행했다. 한글 2024에서 직접 편집·재저장하는 실험은 창 활성화 실패로 미검증이다.**

후속: [추가 조사·개발 세션 인계](exam_hwp_session_handoff.md)에 중복 미주 ID, 해설 내부 개체, 숨긴 연결 번호, 글상자·표·앵커의 적용 조건을 보강했다. 재시도에서 Windows 잠금 화면을 확인한 기록도 아래에 보존했다.

가장 먼저 해결할 문제는 공개 편집용 HWPX의 **미주 번호를 문항 경계로 인식하고, 해설을 해당 문항에 연결하는 것**이다. 공개 파일 4개를 현재 `import_hwpx`에 넣으면 각각 1개 문항으로 합쳐졌다. 이는 서식 취향의 차이가 아니라 실제 가져오기 기능의 실패다.

## 조사 방식과 실행 범위

| 단계 | 방법 | 이번 실행 결과 |
| --- | --- | --- |

기존 자료의 명칭·출처 범위는 [레퍼런스 목록](../../reference_samples_manifest.md)을 따른다. 표본은 확률 표집이 아니다. 공개 4종은 같은 제작자의 변환본이므로, 이를 전체 교육청·평가원 HWP의 보편 규격이나 공식 원본으로 해석하지 않는다.

## 실제 파일에서 확인한 특징

### 용지·구역·단은 파일마다 다르다

| 표본 | 계측한 용지 크기, mm | 단 구성 / 간격 | 미주 |
| --- | --- | --- | ---: |
| 수학 편집본 4종: 2024년 3·5·6월, 2025학년도 수능 | 약 257×364 | 2단 / 약 8mm | 각 46 |
| 로컬 평가원 수학·과탐·사탐 양식 | 약 272×394 | 1·2단 혼합 또는 2단, 약 9.5~12.4mm | 0 |
| 로컬 평가원 국어·영어 양식 | 약 297×420 | 1·2단 혼합 또는 2단 / 약 11mm | 0 |
| 학교 기출 양식 | 약 210×297 | 2단 / 약 8mm | 0 |
| 로컬 2026년 6월 고1 국어 / 수학 | 약 297×420 | 1·2단 혼합 또는 2단 / 약 6mm | 0 / 30 |
| 공개 HWPX 4종 | 약 210×297 | 2단 / 약 6mm | 아래 표 |

위 치수는 원본의 저장 설정이다. 모든 모의고사를 A4·특정 여백·같은 글꼴로 만드는 규칙의 근거가 아니다. 첫 쪽 제목과 뒤쪽 머리말, 공동지문, 선택과목 경계 때문에 한 파일 안에서도 구역·단 정의가 달라질 수 있다.

HWP 계측은 한컴의 [파일 형식 5.0 문서](https://cdn.hancom.com/link/docs/%ED%95%9C%EA%B8%80%EB%AC%B8%EC%84%9C%ED%8C%8C%EC%9D%BC%ED%98%95%EC%8B%9D_5.0_revision1.2.pdf)의 용지·단·컨트롤 구조와 1/7200인치 단위를 사용했다. 2024년 6월 수학의 미주 46개·수식 1,885개는 별도 rhwp IR 순회와도 일치했다.

### 인쇄용 원본과 수업용 편집본의 용도를 구분해야 한다

[공개 제작자 설명](https://www.my1ta.com/blog/2026-june-mock-exam-hwpx-collection)은 문항 발췌·이동·수업 자료 재구성과 미주를 이용한 문제·해설 연결을 강조한다. 실제 [영어·사회·한국사 첨부](https://blog.naver.com/my1ta/224306876900)와 [국어·수학·과학 첨부](https://blog.naver.com/my1ta/224306864261)를 확보해 그 구조를 확인했다.

| 공개 파일 | 미주 | 네이티브 수식 | 표 | 그림 | 글상자 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 국어 화법과 작문 | 45 | 67 | 23 | 5 | 1 |
| 수학 | 46 | 1,696 | 38 | 18 | 5 |
| 영어 | 45 | 21 | 15 | 3 | 0 |
| 지구과학Ⅰ | 20 | 501 | 45 | 18 | 1 |

모든 개체 수는 **해설·중첩 표·머리말을 포함한 전체 문서 구조**의 수다. 수식 1개가 문항 1개를 의미하지 않는다. 미주도 일반 문서에서는 문항 수의 정답이 아니며, 여기서는 제작자의 문항 번호 사용 설명과 파일 구조를 함께 근거로 사용한다. 46개 미주가 있는 편집본에 문항 수 30을 일괄 적용해서는 안 된다.

공개본에는 본문 `hp:p`가 수백 개 있고 문항마다 글상자가 있는 구조는 아니다. 반면 현재 프로젝트의 생성 국어·수학·영어에는 문항용 글상자가 각각 45·30·45개 있다. **문항당 글상자 하나는 이 프로젝트의 기존 요구사항이며 유지한다.** 다만 이를 한글 시험지 전체의 표준 구조라고 보지는 않는다. 내용을 늘릴 때의 상자 높이·뒤 문항 이동·단 경계 검증이 추가로 필요하다.

공개 수학·영어의 rhwp 첫 쪽은 두 단에 각 문항 하나와 넓은 풀이 공간을 보여 준다. 원본 시험지의 쪽별 밀도를 그대로 복원하는 목적과 다를 수 있다. 따라서 이 공개본을 PDF 원본 배치의 정답 이미지로 쓰지 않는다. 이번 첫 쪽들은 실제 2단으로 렌더됐으므로 README의 “다단 양식은 미리보기에서만 1단”이라는 일괄 설명도 이번에 수정했다. 이는 모든 파일의 한글 표시와 일치한다는 판정이 아니다.

### “편집 가능”은 개체별로 나눠 확인해야 한다

본문은 문장 중간에 입력할 수 있어야 하고, 수식은 수식 편집기에서 분자·첨자를 고칠 수 있어야 한다. 표는 셀 안의 문자를 수정할 수 있어야 한다. 그림은 그림 개체로 이동·크기 변경할 수 있다는 뜻과, 그림 안 글자·곡선을 각각 편집할 수 있다는 뜻을 구분해야 한다. XML에 수식·표·그림이 존재하는 것만으로 각 동작의 성공을 증명할 수 없다.

원본의 글꼴 정의 목록에는 사용하지 않는 글꼴도 포함될 수 있다. 이번 도구는 정의 목록만 수집하며, 이를 실제 본문 글꼴의 사용 비율로 해석하지 않는다. 서로 다른 시험과 해설 포함 여부가 다른 파일 사이의 수식 개수 차이를 누락률로 계산하지도 않는다.

| 문항 재배열·삭제 | 사본에서 세 문항을 3→1→2로 이동한 뒤 하나 삭제. 미주 번호 제어와 문항 소속 개체까지 함께 선택 | 표시 번호·정답·해설·그림의 연결 유지. 삭제 문항의 연결 해설만 제거 |

공동지문은 해당 문항 묶음과 함께 옮기는 경우와 한 문항만 발췌하는 경우를 따로 검사한다. 본문 번호, 원출처 번호, 현재 시험지의 표시 번호를 별도로 보관해야 한다. 문항 이동의 식별자는 번호 문자열보다 안정된 문항 ID가 적합하다는 것이 이번 설계 제안이다.

## 실제 앱 엔진에서 재현한 실패

`scripts/probe_exam_hwpx_import.py`는 매번 새 폴더에 연구용 DB를 만들고 현재 `app.importers.import_hwpx`를 호출한다. 사용자 DB에 자료를 추가하지 않는다.

| 공개 입력 | 원본 미주 | 가져온 문항 | 번호 | 정답 / 해설 필드 |
| --- | ---: | ---: | --- | --- |
| 영어 | 45 | 1 | 빈 값 | 0 / 0 |
| 수학 | 46 | 1 | 빈 값 | 0 / 0 |
| 국어 화작 | 45 | 1 | 빈 값 | 0 / 0 |
| 지구과학Ⅰ | 20 | 1 | 빈 값 | 0 / 0 |

미주 안에서 길이가 20자 이상인 텍스트를 표본으로 잡아 대조했을 때, 그 텍스트가 가져온 `stem`에 그대로 포함된 건수는 영어 3, 수학 17, 국어 2, 지구과학 14였다. 이는 혼입의 증거다. 문장 정규화·표 처리 영향 때문에 나머지가 모두 사라졌다고 해석하지는 않는다.

코드의 `import_hwpx`는 최상위 문단 안을 순회하면서 표·수식 내부를 별도로 처리하지만 `endNote` 본문을 격리하지 않는다. 미주와 자동 번호 제어도 문항 번호로 해석하지 않는다. HWP 경로의 `_ordered_stream`은 `ir.body`를 읽으며, rhwp가 별도로 제공하는 `ir.furniture.endnotes`의 해설 연결을 다루는 작업도 필요하다. 이번 4종의 실행 판정은 HWPX 경로에 한정한다.

작은 자작 예제에서도 같은 현상을 확인했다.

| 자작 3문항 입력 | 가져온 문항 | 미주 설명이 stem에 혼입 | 판정 |
| --- | ---: | ---: | --- |
| 미주 번호만 사용 | 1 | 3/3 | 실패 재현 |
| 본문 번호 + 앞쪽 미주 제어 | 1 | 3/3 | 번호 글자 추가만으로 해결되지 않음 |
| 본문 번호만 사용, 미주 없음 | 3 | 해당 없음 | 문항 경계는 분리. 첫 번호는 빈 값, 뒤 번호는 2·3이어서 번호 보존은 추가 실패 |

현재 엔진의 실패를 기록한 것이며 이 조사에서 변환 엔진을 수정하지 않았다. 진단 명령의 종료 코드 0은 측정 실행 성공을 뜻하고, 변환 품질 합격을 뜻하지 않는다.
