## 이번 개발

- **문단 연결:** 원본 오른쪽 여백까지 이어지는 본문은 마침표가 있어도 다음 줄과 같은 문단에 넣는다. 짧은 마지막 줄·새 들여쓰기·문항/선지/보기 시작은 실제 경계로 유지한다. `[A]` 같은 지문 옆 표식의 좁은 너비·높이가 본문 문단을 쪼개지 않도록 했다. 한 문항 안에 여러 의미 문단이 있을 수 있으며, 문항 전체를 무조건 하나의 문단으로 합치지는 않는다.
- **독립 문단 검사:** 원본 PDF의 줄 좌표와 출력 ZIP/XML의 실제 `hp:p`를 대조한다. 문단을 줄마다 분리하거나 강제 줄바꿈을 넣은 변조 파일을 거부하고, 편집성 검사에 연결해 API에서도 차단한다. 줄 캐시의 UTF-16 문자/개체 오프셋도 확인한다.
- **문항 소속:** 표 내부의 `1., 2.`를 새로운 시험 문항으로 오인하지 않게 했다. `확 인 사 항`처럼 자간을 띄운 문서 끝 안내는 마지막 문항 내용에서 분리한다. 문항 내용의 소속과 실제 글상자 크기 검사는 유지한다.
- **문자·수식:** `① $100 … ⑤ $120`을 수식으로 삼키는 문제와 `αi`가 `alphai`라는 한 토큰이 되는 문제를 고쳤다. `$2$`, `2π`, 음수·빼기·근호·로그가 포함된 명시적 수식도 회귀에 포함했다. 원문 비교에서 `t NEQ 2)`의 닫는 괄호를 선지 번호로 오인하는 오류도 수정했다.
- **제목 계층:** 괄호 없는 `국어영역/수학영역/영어영역`도 원본 글자 크기를 측정한다. 제목과 같은 PDF 줄에 붙은 큰 페이지 번호를 제목 크기로 사용하지 않는다. 본문에 배정한 높이는 유지한다.

## 엄격 판정 범위

| 항목 | 통과 조건 |
| --- | --- |
| 문항 글상자 | 실제 번호·개수·순서와 원문 소속 일치, 실제 내용보다 작은 상자 거부 |
| 문단 | 원본에서 연결 근거가 있는 두 줄이 같은 실제 문단에 있고 순서가 유지됨 |
| 편집 재저장 | 글자 추가 후 같은 문단/글상자, 줄 재배치·높이 확장, 출력 영역 안에 실제 글자 표시 |
| 수식·표 | 존재 개수뿐 아니라 원본 수치·연산자·첨자·분자/분모·셀 위치 대조 |
| 그림 | 원본 비트맵 목록·영역·실제 바이트/픽셀·문항 소속 대조, 본문 이미지 덮개 금지 |
| 원본 배치 | 전체 페이지 비교. 기존 엄격 점수 목표 평균 97·최저 95 및 전경/정렬 조건 유지 |

문단 검사는 열 오른쪽 여백에 가까운 연속 정렬 본문을 대상으로 한다. 짧은 시·목록·그림 옆 줄은 연결을 임의로 추정하지 않는다. 혼합 수식 줄은 한글 본문 연결과 별도 수식 의미 검사를 함께 적용한다. 검사한 줄 쌍 수를 전체 문단 수나 모든 문단의 완전한 검증으로 표현하지 않는다.

한컴 GUI에서의 편집·저장·자동 높이 동작은 별도 미검증이다. 이번 재저장 검사는 프로그램의 문단 API와 rhwp 실제 렌더 기준이다. 자동 OCR은 현재 NoOcrBackend이며, 디지털 PDF 검사 결과를 스캔 문서 지원으로 확대하지 않는다.

## 육안 점검에서 남은 문제

국어·수학·영어의 실제 출력 페이지도 확인했다. 특히 수학 첫 페이지는 원본의 넓은 문항 사이 풀이 여백이 사라져 문항들이 위쪽으로 몰린다. 쪽수가 같고 모든 수식이 존재해도 원본 배치 통과가 아니다. 국어의 노트 장식 테두리와 영어 안내 상자 일부에는 배경과 본문이 겹치거나 중복되어 보이는 문제가 있다. 그림 출처 검사 실패와 함께 해결해야 하며, 본문 크롭이나 검사 임계값 완화로 처리하지 않는다.
