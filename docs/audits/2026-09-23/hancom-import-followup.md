# 한컴 GUI·가져오기 실물 후속 검증

2026년 6월 고1 영어 PDF에서 생성한 HWPX **복사본**을 한글 2024에서 열었다. 시작 화면의 팝업은 우상단 **X**로 닫은 뒤 파일을 열었다. 영어 27번의 `∙ Limited to 50 students`를 문서 안에서 `∙ Limited to 60 students`로 직접 수정하고 저장·닫기·재열기했다. 수정 문구는 재열기 후에도 남았다. 원본 출력 파일은 변경하지 않았다.

| 항목 | 실측 결과 |
| --- | --- |
| 원본 영어 PDF | 8쪽 |
| 생성 HWPX의 rhwp 렌더 | 8쪽 |
| 생성 HWPX 복사본을 한글에서 열었을 때 | **10쪽** |
| 한글에서 수정·저장·재열기한 뒤 | **10쪽**, 수정 문구 유지 |
| 한글 저장본을 rhwp로 다시 읽었을 때 | **10쪽** |

따라서 이전의 rhwp 8쪽 일치는 한글에서의 페이지 일치를 증명하지 못한다. 이 결과만으로 36쪽 전체의 한글 페이지 수를 일반화하지 않는다. 한글 저장본은 패키지 검증에서 유효하지만, 매니페스트의 version 파트 누락 경고 1개가 있다. 생성본과 저장본의 `hp:t` 문자열은 29,117자와 29,105자이고, 차이는 수정 숫자 `5 → 6`과 중복된 머리말 12자의 제거다. 기존 생성본용 구조 검사는 저장본에서 9개 항목을 실패로 판정했다. 한글이 XML 구조와 자산을 다시 쓰므로, 이 판정을 곧바로 실제 그림 손실로 해석하지 않는다. **한글 재저장본의 시각 비교와 페이지 차이의 원인 분석은 미완료**다.

브라우저로 로컬 앱을 열어 HWPX 업로드를 시도했으나 사용 중인 브라우저 도구가 파일 선택 이벤트를 받지 못했다. 따라서 브라우저 화면에서 가져오기 완료까지 검증했다고 주장하지 않는다. 같은 로컬 앱의 `/api/import`는 격리된 저장소에서 실행해, 수정 전 영어 1개·번호/정답/풀이 없음에서 수정 후 **영어 45개, 번호 1–45, 정답 45개, 풀이 45개**로 바뀐 것을 확인했다.

임포터는 순차 번호와 정답 표식이 충분한 HWPX 미주를 문항 경계로 사용한다. 미주 안의 정답·풀이를 본문에서 분리하고, 미주 안 그림은 해당 문항에 붙인다. 이런 구조가 아닌 파일은 기존 문단 기반 분리를 유지한다. 4개 실물 원본을 각각 격리된 DB로 가져온 엄격 검증 결과는 아래와 같다.

| 원본 | 번호 붙은 미주 | 생성 문항 | 정답/풀이 | 미주 긴 문구의 본문 누출 | 그림 연결 | 5개 선택지가 별도 필드인 문항 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 영어 | 45 | 45 | 45/45 | 0 | 3 | 31 |
| 수학 | 46 | 46 | 46/46 | 0 | 18 | 0 |
| 국어 | 45 | 45 | 45/45 | 0 | 0 | 44 |
| 지구과학 | 20 | 20 | 20/20 | 0 | 18 | 0 |

수학·지구과학의 선택지는 원문 표 안에 남아 있으며 개별 선택지 필드로 분리되지 않았다. 일부 영어 문항도 그렇다. 문항 수와 정답 수만으로 가져오기 정확도를 완료 판정할 수 없는 이유다. 표가 있는 미주형 문항은 앱에서 확인 안내를 표시한다. 이 네 원본의 번호·정답·풀이·미주 누출 회귀와 기존 임포터 회귀는 통과했지만, 표 안 선택지의 의미 단위 분리, 한글 페이지 차이, 브라우저 UI 업로드 완료는 아직 해결되지 않았다.
