## 그래프 중복과 소속 수정

수학 11쪽 27번은 원본 비트맵 두 조각에 곡선·축이 있고, 점 이름과 함수식 10개는 PDF 텍스트층에 따로 존재한다. 기존 변환은 이 영역 전체를 렌더링한 그림과 같은 글자의 독립 문단을 함께 출력했다. 글자가 중복되고 그래프도 아래로 밀렸다.

이제 원본 비트맵 개체만 합성해 곡선·축을 보존하고, **일반 글자 7개와 네이티브 수식 3개**를 원본 상대 위치의 편집 개체로 만든다. 그림과 표기는 실제 `hp:container` 그룹으로 묶어 기존 문항 글상자 내부 문단에 넣는다. 별도의 본문 표기 문단은 남기지 않는다. 그래프 자체의 주석을 묶는 구조이며, 문제의 문장은 계속 의미 문단 하나로 이어진다. 렌더러 바이너리는 수정하지 않았다.

원본 그래프와 출력 SVG를 직접 비교한 최대 위치 오차는 **0.012691px**로 0.1px 기준을 통과한다. 이전의 그림 세로 오차는 +12.7757px였다. 11쪽 배치 점수는 같은 환경 기준 **87.15 → 94.32**다. 그래프와 표기가 실제 출력에서 한 번씩 표시되는지도 확인했다.

인식은 축 `x`, `y`, 대문자 점 이름, 제한된 함수 표기와 원본 비트맵 소속이 확인되는 희소 그래프에 한정한다. 축이 없거나 그림 소속이 겹치거나 표·본문이 침범하는 경우에는 적용하지 않는다. 모든 그래프나 비트맵 안에 박힌 글자를 네이티브로 변환한다는 뜻은 아니다.

## 문단 편집과 독립 검증

점 이름 `A → R`은 문서 API로 수정하고, 네이티브 수식 `y=f(x) → y=h(x)`는 수식 XML을 수정해 저장·재열기와 실제 표시를 확인했다. 수식 전용 공개 편집 API나 한컴 GUI를 시험했다는 의미는 아니다. 앞의 문제 문단에 **244자**를 추가하면 문단 수·비트맵·12쪽을 유지하며 그래프와 표기 전체가 **124.4px** 아래로 이동한다.

영어 18번의 인사말·본문·서명은 3개 의미 문단이고, 본문 10줄은 같은 `hp:p`다. +158·316·474·790자 편집·재저장에서도 위아래 장식 높이와 내용의 비겹침을 유지한다. 수학 14번은 인쇄 20줄을 13개 의미 문단으로 유지하며 +162자 편집 후 빈칸 8개·네이티브 수식 191개·재저장을 통과한다. 국어 병합 셀·그림 옆 문단과 반복 머리말·선택지 탭도 다시 검사했다.

원본 검사기는 생성기의 개수나 개체 이름만 신뢰하지 않는다. 실제 PDF 표기 목록과 출력 문항의 그룹·문자·크기·좌표·잠금·변환행렬을 대조한다. 그래프 영역의 글자는 네이티브 원문 대조 대상에 그대로 포함한다. 패키지만 검사하는 도구의 구조 판정과 원본을 가진 검사의 내용 판정을 구분한다.

- 표기 누락·중복·잘못된 글자·이동·잠금·상자 축소·그룹 확대·그룹 밖 중복 등 8개 변조를 거부한다.
- 비트맵 픽셀과 출처 해시를 함께 바꿔도 원본 개체로부터 독립 복원한 픽셀과 달라 실패한다. **한 픽셀 변경**이 아홉 번째 음성 사례다.
- PNG 인코딩만 바꾸고 디코딩 픽셀이 같은 경우는 통과한다.
- 표기 누락·이동 각각 `structured`와 `coordinate`에서 **422**를 반환한다. 보존율 100%의 위조 통계도 이를 우회하지 못하고, 거부된 출력은 정리된다.

## 같은 환경의 전후 비교와 재현성 한계

이전 보고서의 HWPX 바이트는 당시 SHA-256과 일치한다. 이 파일을 재변환 없이 현재 환경에서 다시 렌더링하니 **36쪽 모두 과거 PNG와 달랐다**. 설치된 렌더러는 보존한 wheel의 바이너리와 일치하며 `rhwp-python 0.7.0+nativecell1`, core 0.7.13이다. 원인은 아직 특정하지 못했다. 글꼴 차이로 단정하거나 원본 글꼴 문제가 해결됐다고 보고하지 않는다.

| 과목 | 쪽수 | 과거 보관 점수 | 이전 파일의 현재 환경 점수 | 새 결과 | 새 결과 최저 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 국어 | 16 | 86.55 | 85.80 | 85.80 | 75.95 |
| 수학 | 12 | 88.23 | 88.07 | 88.67 | 76.86 |
| 영어 | 8 | 87.45 | 87.09 | 87.09 | 72.20 |

36쪽 평균은 페이지별 점수에서 계산했다. 표에 반올림된 과목 평균을 다시 가중하면 0.01 차이가 날 수 있다. 개발 전후에 비교한 원본 PDF 렌더 픽셀은 36쪽 모두 같다. 출력은 국어·영어 전체를 포함한 **32쪽이 픽셀까지 같고**, 수학 4·8·9쪽은 각각 2·1·4픽셀 차이지만 점수는 같다. 수학 11쪽만 점수가 상승했다. 역사적 점수와 현재 점수를 섞어 국어 퇴행 또는 전체 향상을 주장하지 않는다.

## 남은 실패와 평가 범위

전체 회귀의 실패는 `verify_external_exam_detail_quality.py`다. 원본 대비 엄격 정렬·전경 겹침, 수학 영역 정렬·겹침, 기존 평균 97·최저 95 기준을 충족하지 못했다. 기준을 낮추거나 이 실패를 생략으로 바꾸지 않았다. 실제 국어 `structured`와 수학 `coordinate` 변환·다운로드는 200이고 패키지도 유효하지만, API 품질 점수 **85.80·88.67**은 통과가 아니다. API의 기존 98점 기준과 이번 개발 목표 93점은 구분한다.

API 구조 점수에서는 원본 검증을 통과한 빈칸 프레임 8개와 그래프 표기를 정상 내부 개체로 집계하도록 수정했다. 수학의 과거 API 점수 83.50과 현재 88.67의 차이에는 이 집계 수정도 포함되므로 전부 시각 품질 향상으로 해석하지 않는다. 실제 렌더 점수가 총점을 제한하는 규칙은 유지한다.

남은 작업은 다음과 같다.

1. 렌더 재현성 원인 확인과 원본 글꼴·수식 간격·전 페이지 배치 개선.
2. 수학 9쪽 22번 시작점의 가로 오차 **+0.444919px**, 일반 첫 쪽 머리말 아래 기준선 오차 **+4.081255px** 수정. 수학 2~12쪽 22개 세로 시작점은 최대 **0.003541px**로 0.1px를 계속 통과한다.
3. 꼬리말·첫 쪽 자동 번호, HWPX 미주와 문항 소속 가져오기 수정. 공개 4종의 미주 가져오기 실패는 이전 재현 결과이며 이번에 해결하지 않았다.
4. 최신 소스의 21과목 168쪽 재평가와 실제 한컴 GUI에서 편집·저장·재열기 확인.

원문 텍스트층 대응은 국어 **27,028/27,028**, 수학 **1,609/1,609**, 영어 **23,681/23,681**이다. 대응률 100%는 그림 속 글자·전체 읽기 순서·모든 의미 정확도의 증명이 아니다. 패키지와 rhwp의 편집 검증도 실제 한컴 검증을 대신하지 않는다.
