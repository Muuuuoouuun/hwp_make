# Actual raster masthead preservation: read-only assessment

Preserving the original masthead graphic is compatible with ordinary editable question bodies. It would replace an invented font approximation with the source's actual graphic. It would deliberately make the four masthead characters a selectable picture, while all 45 question bodies, choices and equation objects remain native and editable. No masthead app change or package A/B is made in this review.

## Actual source evidence

High 3 page 3 uses image xref 60 at `[365.2200012, 111.9610596, 477.0939941, 140.3410645]` points on an 842×1191-point page. It is a 1356×344, 8-bit DeviceGray, FlateDecode image without a soft mask. Its extracted PNG is 38,579 bytes with SHA256 `26f7997aa9b995910c2d65ab993153d5ffe386166f54e26186393325036b4849`. Its painted box is only 0.3166% of the page. The image's native physical box is `[258.2044810, 79.1546114, 337.2975378, 99.2188040]` points after page-width scaling.

There are no extracted text characters inside that box. The only intersecting source paint operation is sequence 2, `fill-image`; no later rectangle/text overlaps the heading. The heading has no font program to recover. The source PNG and source/native rendered crops are saved under `tmp/september-audit/raster-masthead-review/` and visually inspected. The native approximation is visibly different in strokes and spacing. At a common 342×105 crop and 288 DPI, source versus current native has mean RGB absolute difference 49.293/255 and 24.09% pixels differing by more than 24. These are descriptive crop statistics, not a proposed pass threshold.

Running pages 2–8 reuse xref 60. Odd/even source matrices differ slightly in horizontal width: 111.873993 versus 111.768005 points. First page uses a distinct 1348×344 heading image xref 129 at a larger 161.760010×41.279999-point box. A replacement must preserve each actual source image and parity geometry, rather than stretch one hardcoded page-3 box over the booklet.

## Current ownership and validation

`pdf_masthead_typography.py` already independently identifies all eight source mastheads as full/running English headers, using official title, period/variant/page fields, a unique header image slot, separator rule and coherent source page geometry. Its raster path explicitly reads only the image box and synthesizes native `영어 영역` in a fallback face (Malgun Gothic in this source). `pdf_masthead_flow.py` places that text in ordinary header table cells named `source-page-masthead:area`; the fresh high 3 package has three such XML owners: first-page BOTH and repeating EVEN/ODD. The source area image is currently omitted from body image extraction.

Existing image validation does not establish masthead-image completeness: `inspect_source_images` explicitly excludes images above the measured body top. However, the general package picture audit still examines pictures inside headers, requires resolved assets, complete crop, declared usage/provenance and acceptable native picture geometry, and rejects front-of-text pictures. Provenance currently allows only source-figure/background roles. The existing `bitmap_objects` path compares a deterministic decoded source-image composition and is preferable to a loose page-crop tolerance if its exact dimensions are retained.

Directly embedding the 1356×344 original PNG is not automatically covered by the current `bitmap_objects` composer, which produces a fixed source-region canvas. It needs either a narrow original-object pixel validator or an explicitly measured composition asset under the existing contract. A digest or role label alone must not authorize the image. All used pages/parity headers must independently prove source ownership; shared XML header uses and repeated painted pages have different counts.

## Bounded temporary A/B plan

1. Work only on a copy of the authoritative fresh high 3 native package. Resolve the three existing area header cells and their actual full/odd/even source masthead records. Re-extract the uniquely matched, visible source image objects; preserve complete decoded pixels, mask and actual affine geometry. Reject ambiguity, rotation/shear, clipping, mask handling not implemented, overlapping native source text, or later opaque coverage.
2. Replace only each area's native text run with one ordinary inline picture. Keep the same cell, header table, row/cache height, cell top margin, separator rule, page fields and section margins. Use public image/picture APIs and derive width/height from each actual image box. Do not put raster text over hidden duplicate native heading glyphs. Verify native inline-picture baseline placement by actual rendering.
3. Record narrow source-image provenance linking exact page, image number/xref, transform, complete source pixels and owner header. Validate decoded pixel identity independently of the writer's digest. Keep body-image completeness and all prose-raster rejection rules intact; do not grant a generic header exemption for arbitrary pictures.
4. Render every page before/after. Compare the masthead to the source at common physical geometry; require every question's native text, run styles, cache/geometry and painted glyph inventory/positions to remain exactly unchanged. Check page fields/rules and every pixel outside the replaced masthead areas for unintended changes. Whole-PDF native glyph count intentionally loses the generated four-character heading on each page, so body-only and outside-area invariance are the meaningful contracts.
5. Publicly append/edit a body, save/reopen/resave and verify its native flow and picture identity. Also test header image replacement/deletion, missing or wrong asset, forged source object/transform/role, duplicate picture, wrong parity/full-page source binding, cropped picture and missing page seed. Require all 45 question units and body editability gates to pass without scorer changes.

This experiment would address visible source fidelity without selecting another approximate font. Adopting it changes the existing native-header-text policy and should be evaluated explicitly; it does not require rasterizing any question prose.
