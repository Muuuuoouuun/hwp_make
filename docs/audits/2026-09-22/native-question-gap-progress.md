## 수정한 동작과 회귀 방지

문항 글상자의 바깥 문단 여백이 다음 문항 위치에 반영되지 않는 읽기 엔진의 동작을 확인했다. 원본에서 측정한 빈 공간을 인접한 실제 글상자의 위·아래 내부 여백으로 표현하고, 개체 크기·원래 크기·사각형 꼭짓점·편집 영역·호스트 줄 높이를 함께 갱신한다. 본문 이미지 덮개, 빈 문단, 추가 도형, 글자 크기 조작을 사용하지 않는다.

현재 읽기 엔진은 글상자 여백을 16비트 정수로 읽는다. 32,767을 넘긴 큰 여백이 사라지는 실패를 발견해 인접 글상자의 앞뒤 여백에 나누어 저장하도록 수정했다. 문단 편집으로 공간이 부족해지면 초기 PDF 변환과 동일하게 측정된 빈 여백을 먼저 줄인다. 그래도 내용이 넘치면 문항 전체를 다음 단으로 이동한다. 한 문항 자체가 한 쪽보다 크면 오류로 차단한다.

재배치 과정에서 추가한 문단 스타일도 헤더에 반드시 저장한다. 처음에는 스타일 ID가 본문에만 남아 다시 열고 저장할 때 실패했으며, 헤더 수정 상태를 함께 반영해 고쳤다. 원래 스타일을 제자리에서 바꾸지 않고 해당 문단용 복사본을 만든다.

새 `scripts/verify_native_question_gap_reflow.py`는 실제 PDF를 만들어 18개의 연속 문단을 변환한다. 원본 PDF 기준선 간격을 **0.1px** 이내로 대조하고, 두 줄 이상 자동 줄바꿈, 큰 여백, 문장 추가·대량 삭제, 실제 단 넘김, 전체 문구 표시, 페이지 범위, 뒤 문항 비겹침, 재열기 후 저장, 스타일 참조와 사각형 경계를 검사한다. 기존 산문·표·운문 검사도 유지했다.

검사 표현도 변경했다. 머리말 적용 전후에는 바깥 여백 포함 상자 높이가 달라질 수 있으므로, 이전의 단순 전체 높이 동일 검사를 **실제 편집 영역 높이·텍스트 높이·문단 내용·모든 본문 줄 캐시 속성 동일** 검사로 바꿨다. 뒤쪽 페이지 좌표 동일과 머리말 0.1px 검사는 그대로다. 공통 지문 편집의 독립 probe는 신규 여백 스타일 추가를 허용하되 원래 헤더·스타일·그림의 불변, 추가 스타일에서 앞뒤 여백 외 속성 불변을 확인한다. 위치·품질 허용 오차를 넓히지 않았다.
