## 수정 내용과 엄격한 검사

`ITEM_01`, `file_name`, `output_2026_report`가 아래첨자 수식으로 바뀌는 경우를 수정했다. 짧은 수학 변수와 명시적인 수식 표기는 유지한다. 검증기는 원본 PDF의 일반 글꼴에서 식별자를 직접 읽어 밑줄과 출현 횟수를 별도로 확인한다. 수식 기호 정규화는 실제 수식 노드에만 적용한다. 예전 출력은 밑줄이 없어졌는데도 편집성 검사를 통과했지만, 새 검증기는 같은 파일을 실패로 판정한다.

실제 PDF의 네 줄을 한 문단으로 변환한 뒤 파일명을 바꾸고 문장을 늘려 재저장했다. 밑줄 삭제·숫자 변경·텍스트를 수식 노드로 대체·두 번째 출현 누락의 네 손상 파일을 모두 잡았다. [검사 결과](../../../data/verification/20260922_goal_native_diagrams_final_r3/literal_contract/report.json), [이전 잘못된 출력의 새 검증 결과](../../../data/verification/20260922_goal_native_diagrams_final_r3/previous_literal_output_rejection.json).

도형 주변의 단일 라벨이 일반 문단으로 흘러 내려가던 원인을 수정했다. 서로 다른 가장자리에 있는 여러 라벨, 한 개의 명확한 원본 비트맵, 제한된 확장 범위, 본문·수식·표와의 비겹침이 확인될 때만 같은 원본 그림 범위로 묶는다. 실제 PDF에서 그 범위를 다시 렌더해 픽셀과 원본 비트맵 목록을 확인한다. **수학 4쪽의 6개, 7쪽의 11개 라벨은 이 그림에 포함되며 개별 편집 텍스트가 아니다.** 본문은 별도의 네이티브 문단이다.

단독 그림에는 실제 문단에 붙는 `TOP_AND_BOTTOM` 한글 그림 개체를 사용한다. 원본 가로 위치·크기를 저장하고 문서 흐름에 그림 높이를 확보한다. 그림은 앞 문단의 편집에 따라 이동한다. 옆으로 본문이 흐르는 그림과 표 셀 그림은 해당 구조에 먼저 배정한다. 본문 중복, 겹침 허용, 페이지에 고정된 좌표, 단 밖 이동, 높이 확보 누락은 검증에서 거부한다.

텍스트 추가 API `HwpxOxmlParagraph.add_run`이 기존 줄 배치를 무효화하지 않아 새 텍스트가 배치에 반영되지 않던 결함도 수정했다. 문단 전체 교체와 같은 배치 갱신 절차를 사용한다. 실제 수학 12번의 수식 포함 문단에 **197자**를 추가했을 때 그림은 **140.827px** 아래로 이동했다. 문단 수·그림 바이트·모든 수식 스크립트와 12쪽을 유지했고, 새 텍스트가 실제로 표시되며 새로 열어 재저장한 결과도 같았다.
