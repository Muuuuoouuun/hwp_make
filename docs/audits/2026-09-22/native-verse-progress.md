## 구현과 검사 범위

- 공통 지문 단일 셀의 원문 전체 대응, 동일한 문자 스타일, 작품 출처, 여러 짧은 행의 정렬·오른쪽 끝·기준선 간격이 확인되는 경우만 운문으로 재구성한다. 연 사이 간격은 문단 뒤 여백, 연 안의 행 구분은 네이티브 `lineBreak`로 표현한다. 출처가 없거나 일반 산문·번호 목록인 경우에는 이 재구성을 적용하지 않는다.
- 공개 문단·run API가 네이티브 줄바꿈과 탭을 읽고 쓸 때 유지한다. 줄바꿈 뒤 XML tail 텍스트를 누락하지 않으며, 수정으로 줄 캐시가 없어져도 실제 줄바꿈을 기준으로 다시 조판한다. 보조 평면 문자의 UTF-16 길이도 반영한다.
- 오른쪽에 있는 작품 출처를 큰 왼쪽 들여쓰기가 아닌 오른쪽 정렬 문단과 원본의 오른쪽 여백으로 표현한다. 첫 시도에서 출처가 같은 내용 재저장 후 두 줄로 꺾이는 문제를 발견하고 수정했다. 현재 두 출처 모두 한 줄을 유지하지만 원본 시작점 오차는 커졌으므로 배치 품질 개선으로 판정하지 않는다.
- 일반 산문을 줄별 문단이나 강제 줄바꿈으로 고정한 결과를 거부하는 기존 검사를 유지했다. 수식·그림·표를 숨기거나 이미지로 덮는 우회를 추가하지 않았다.
- 새 `verify_native_verse_paragraphs.py`는 실제 PDF 생성·변환, 연 단위 문단, native break, 실제 SVG 행 순서, 원본 행·연 간격의 0.1px 검사, 공개 문단·run 수정, 표 성장, 재저장, 잘못된 원문 경계 거부를 포함한다. 실물 검사에서는 합성 자료와 별도로 PDF에서 직접 읽은 39개 행을 대조했다.

첫 전체 회귀에서 단독 배치 함수 호출 시 `ModuleNotFoundError: No module named 'hwpx'`를 발견했다. 공통 텍스트 처리를 문서 패키지 초기화가 필요 없는 `app/_vendor/hwpx_text_content.py`로 옮겼다. 기존 단독 호출 검사와 운문·공통 지문 검사를 다시 통과한 뒤 **r2 소스를 새로 고정하여 36쪽과 전체 회귀를 재실행**했다. 초기 실패 기록을 최종 통과 기록으로 덮어쓰지 않았다.
