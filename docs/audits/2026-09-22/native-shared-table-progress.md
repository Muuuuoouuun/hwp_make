# 공통 지문 표의 문단 배치 수정 및 5분야 재평가

국어·수학·영어 36쪽을 같은 원본과 같은 평가 기준으로 다시 변환했다. 엄격 배치 평균은 **77.52 → 77.93**, 국어 마지막 쪽은 **59.65 → 68.71**이다. **93점 목표와 완성본 판정에는 미달한다.**

공통 지문 표에서 원본 39개 줄이 실제 39개 기준선에 놓이도록 복원했다. 기존 20개 네이티브 문단을 유지하며 줄별 글상자를 추가하지 않았다. 다만 시의 의도적인 행 구분은 아직 문단 내부의 줄 캐시에만 남는다. 동일한 문장을 문단 setter로 다시 지정하면 원래 두 행이 한 행으로 합쳐지는 결함을 재현했다. 초기 외관 개선을 수정 후 행 보존 통과로 보고하지 않는다.

## 이번 구현

- 공통 지문 표의 전체 텍스트와 원본 줄이 순서대로 정확히 대응할 때만 문단별 줄 캐시·들여쓰기·문단 뒤 간격을 복원한다. 다른 문구, 누락 줄, 셀 폭을 벗어나는 줄은 변경 전에 거부한다. 일반 산문에는 강제 줄바꿈을 삽입하지 않는다.
- 표 높이 계산에 실제 문단 앞·뒤 간격을 포함한다. 편집 후 행 높이를 갱신할 때도 같은 간격을 반영한다.
- 문항 글상자 밖에 있는 공통 지문 표도 공개 문단 setter와 저장 경로를 통해 줄을 다시 계산하고 표 높이를 늘린다. 문단 소속·들여쓰기·문단 간격을 유지한다.
- `verify_native_shared_table_paragraphs.py`를 추가했다. 실제 PDF 생성·변환, 원본의 15/60pt 간격과 첫 줄 10pt 들여쓰기의 0.1px 비교, 잘못된 원본 대응 거부, 문단 편집, 표 성장, 실제 SVG 전체 문구·뒤 문단 비겹침, 재저장을 검사한다. 관련 8개 회귀 모두 통과했다.

주요 코드: `app/pdf_table_paragraphs.py`, `app/pdf_native_typography.py`, `app/_vendor/hwpx/tools/question_reflow.py`. `app/pdf_question_units.py`는 탐색 변경을 되돌린 후 줄 끝 형식만 달라졌으며 AST 비교 결과 동작 차이는 없다. 문항 글상자의 기존 인라인 구조와 검증 조건을 유지했다.

문항 내부의 여러 조각 표는 각 조각의 여백을 문항 전체와 함께 조정해야 한다. 공통 지문용 복원을 모든 조각 표에 적용한 실험은 국어를 17쪽으로 늘려 채택하지 않았다. 문항 글상자를 문단 고정 블록으로 바꾼 다른 실험도 작은 간격 테스트는 통과했지만 실물 국어가 30쪽으로 늘어 되돌렸다. 최종본은 16쪽이며 두 실험의 출력과 로그는 `tmp/korean_lastpage/`에 남아 있다. 실패 실험을 최종 통과 집계에 넣지 않았다.

## 강화한 실물 검사와 실패

국어 16쪽 시의 왼쪽 틀에서 PDF API가 직접 반환한 39개 줄을 실제 SVG 글자 좌표와 대조했다. 생성기의 성공 표식과 별개로 측정했다.

| 항목 | 수정 전 | 수정 후 | 판정 |
| --- | ---: | ---: | --- |
| 네이티브 문단 수 | 20 | 20 | 줄별 문단 추가 없음 |
| 각 원본 줄이 하나의 기준선에 표시 | 아니오 | 예 | 초기 변환 통과 |
| 최대 기준선 간격 오차 | 23.767px | 0.119px | **0.1px 기준 실패** |
| 최대 절대 세로 오차 | 360.081px | 11.865px | **0.1px 기준 실패** |
| 줄 시작점 최대 가로 오차 | 262.890px | 2.464px | **0.1px 기준 실패** |

같은 표 안 문단에 138자를 추가했다. 표 높이는 56,913 → 60,560 HWPUNIT로 증가했고, 문단 수 20개와 문단 여백·들여쓰기를 유지했다. 편집본도 16쪽이며 실제 SVG에 추가 문구 전체가 표시되고 두 번째 저장에서 해당 문단 XML이 안정적이었다.

별도 사본에서는 두 행으로 인쇄된 짧은 시 문단에 **내용이 같은 setter 호출**을 했다. 캐시가 다시 계산되면서 두 행이 한 행으로 바뀌었다. 이 검사는 **실패 종료(1)** 했으며 `verse_noop_setter.hwpx`를 보존했다. 시의 연을 실제 문단으로 묶고 의도적인 행 구분을 네이티브 줄바꿈으로 표현하는 개발이 필요하다. 일반 산문의 물리적 줄을 강제 줄바꿈으로 바꾸어 이 문제를 덮어서는 안 된다.

**전체 회귀의 두 실패:** 외부 시험 품질의 기존 평균 97·최저 95·전경 겹침 97% 기준, 선택지 위치 오차 **7.89px > 6px**. 기준을 낮추거나 실패를 생략으로 처리하지 않았다.

**추가 수학 검사:** 1쪽 1번 기준선 절대 오차 약 0.228px와 간격 오차 0.115px가 별도 0.1px 기준에 계속 실패했다. 세 과목 머리말의 12개 시작점·기준선과 제목 편집·재저장은 기존 기준을 통과했다. 모든 글꼴·테두리 일치까지 뜻하지 않는다.

**하단 겹침:** 국어 16쪽 마지막 선택지와 확인사항은 최종 PNG에서도 겹친다. 기존 SVG를 MuPDF로 다시 래스터화해도 같은 위치의 겹침을 확인했다. 문자열이 각각 한 번 존재한다는 사실만으로 배치나 렌더링을 통과시키지 않는다. rhwp의 인라인 글상자 커서 계산에서 앞 여백이 누적되지 않는 경로를 확인했지만, 대안 배치는 쪽수 회귀 때문에 채택하지 않았다.

**가져오기와 한컴 앱:** 공개 4종 HWPX 미주가 각각 한 문항으로 생성되고 정답·해설이 비어 있는 [기존 재현](../2026-09-21/exam_hwp_session_handoff.md)은 아직 해결하지 않았다. 한컴 GUI 직접 편집도 Windows 잠금 화면으로 인해 미검증이다. 파일 구조와 rhwp 검사를 한컴 직접 편집 통과로 대체하지 않는다.
