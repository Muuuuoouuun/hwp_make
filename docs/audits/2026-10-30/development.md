# HWP Make 개발 점검 (2026-10-30 KST)

이번 작업은 PDF→HWPX 편집·배치, HWPX 가져오기, UI 실행 순서로 진행했다.

## PDF→HWPX 머리말

일부 평가원 PDF는 큰 `영어 영역`/`국어 영역` 글자를 PDF 이미지로 저장한다. 기존 측정기는 텍스트 영역명이 없으면 머리말 전체의 원본 좌표·서체를 버려, 결과의 제목이 위쪽에 크게 나타났다. 교시와 원본 제목이 있고 중앙의 영역 이미지가 하나로 특정될 때, 이미지 위치를 사용해 영역명을 편집 가능한 HWPX 글자로 재구성한다. 본문·표·수식은 이 변경의 대상이 아니다.

로컬 `영어.pdf` 1쪽에서 문항 12개·편집 텍스트 보존율 1.0을 유지하며, 같은 렌더 환경의 엄격 배치 점수가 **65.26→85.88**, 전경 일치율이 **0.6592→0.8775**로 올랐다. `국어.pdf` 1쪽도 편집 텍스트 보존율 1.0, 엄격 배치 점수 85.43, 전경 일치율 0.8847이다. 이는 94점 목표 달성이 아니다. 파일 전체와 한컴에서의 편집·재저장은 별도로 검증해야 한다.

## HWPX 가져오기

미주형 시험지에서 표가 순수하게 ①–⑤ 선택지로만 구성된 경우, 세 가지 표 배치(선지별 셀, 번호·내용 두 열, 번호·내용 두 행)를 선택지 필드로 옮긴다. 다른 글이 섞인 표는 그대로 유지한다. 표 안 그림도 문항 이미지로 보존한다. 합성 HWPX에서 네 문항의 번호, 미주 정답·해설 분리, 선택지, 혼합 표, 표 안 그림을 확인했다. 실제 제작사 HWPX의 복잡한 병합 셀·선지 그림 소속은 추가 표본 검증이 필요하다.

## UI·실행 확인

Chromium에서 합성 PDF를 화면에 넣고 HWPX 변환·다운로드를 완료했다. 다운로드는 ZIP/HWPX 헤더를 가진 파일이며, 품질 미달 안내가 화면에 표시된다. 390·768·1440px에서 가로 넘침이 없고 JavaScript 콘솔 오류가 없었다. 브라우저 전체 자동 회귀는 정적 프런트엔드 검사와 별도로 남아 있다.

이 실행 환경의 프로젝트 가상 환경에는 이전 `rhwp-python 0.7.0` 휠이 있어 시스템 FreeType을 실행 시 선적재해 렌더 검사를 했다. 저장소에 기록된 글꼴 캐시 수정 휠과 동일한 환경이라고 보지 않는다. 머리말·제목·API 관련 회귀 5개, 임포터 회귀 2개, UI·동시성 회귀 5개는 통과했다. 합성 PDF 레이아웃 묶음은 71개 검사 통과·실패 0건이다.

전체 회귀 최초 실행은 **138개 중 110 PASS·23 SKIP·5 FAIL**이었다. 실패 세 건은 이 환경에 없는 `data/uploads/25수능 수학.pdf`를 전제로 한 검사 두 개와, 기준선의 HWP·HWPX 표본 없이 PDF만 비교한 골든 E2E였다. 합성 검사는 그대로 실행하고, 없는 실물 표본은 명시적으로 `SKIP`을 반환하도록 수정했다. 골든 E2E는 있는 PDF의 기준선 값(59문항·18수식·8이미지·재열기 성공)을 검증한 뒤 나머지 표본만 `SKIP` 처리하며, 표본이 빠진 상태에서 `--update`로 기준선을 덮어쓰지 못하도록 막았다. 세 스크립트의 수정 후 재실행은 모두 `SKIP`으로 끝났고 실패는 없었다. 이를 원래 결과에 반영하면 **110 PASS·26 SKIP·2 FAIL**이며, 전체 138개를 수정 후 재실행한 수치는 아니다.

남은 실패 두 건은 배경 이미지 렌더와 중첩 글상자 렌더 검사다. 현재 공식 렌더러에서 실패하며, 변경 전 `origin/work`를 별도 작업 트리에 놓고 같은 실행 환경으로 재현해 기존 실패임을 확인했다. 이전 점검에서는 수정 Linux 렌더러로 이 검사가 통과했지만, 현재 가상 환경에는 그 휠이 없다. 두 검사를 통과했다고 표시하거나 기준을 낮추지 않았다.
