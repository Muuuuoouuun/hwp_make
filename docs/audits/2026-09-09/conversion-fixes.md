# 로컬·웹 변환 품질 및 속도 개선

2026-09-09 작업 결과. 앞선 [진단 기록](local-web-conversion.md)의 실험을 제품 코드에 반영하고, 같은 작업 폴더에 추가된 네이티브 변환 경로의 실제 오류를 수정했다. 설치형 EXE 재빌드와 원격 웹 배포는 이번 결과에 포함하지 않는다.

## 최종 결과

최종 전체 경로 10/10건과 선택지 높이 수정 후 수학 4/4건이 성공했다. 모든 작업의 실행 중 소스 해시가 유지됐고, 로컬·웹 7쌍에서 임의 객체 ID를 제외한 텍스트·수식·서식·그림·패키지 내용이 같았다.

| 입력 | 로컬 worker | 웹 worker | 비교 조건 |
| --- | ---: | ---: | --- |
| 수학 PDF 12쪽 | 14.87초 | 11.42초 | 경로별 2회 중앙값 |
| 영어 PDF 8쪽 | 18.43초 | 18.00초 | 마지막 경로별 1회 |
| 한국사 PDF 4쪽 | 18.39초 | 17.99초 | 마지막 경로별 1회 |
| TXT → HWPX | 1.65초 | 1.57초 | 마지막 경로별 1회 |
| TXT → DOCX | 1.29초 | 1.32초 | 마지막 경로별 1회 |

수학 개별 시간은 로컬 10.54·19.20초, 웹 10.77·12.07초였다. 후반 로컬 실행에서 검수 등 여러 단계가 함께 느려졌다. 반복 수가 적고 실행 부하가 달라질 수 있으므로 웹 엔진 자체가 더 빠르다는 결론을 내리지 않는다. 사용자 체감 시간에는 전송·대기열·화면 갱신 시간이 추가된다.

원문 텍스트 조각 보존 검사는 수학 **99.34%**, 영어 **99.92%**, 한국사 **100%**였다. 수학의 감지된 분수 20개가 모두 네이티브 수식에 포함됐고 미해결 기호는 0개, 독립 검사에서 수식 문단·셀 높이 부족도 0건이었다. 자체 종합 점수는 수학 100·영어 85·한국사 85지만, 이 점수를 의미 정확도나 실제 한컴 편집 품질의 백분율로 해석하면 안 된다. 남아 있는 텍스트 비교 불일치와 페이지 배치 차이는 개별 리포트에 그대로 기록한다.

## 반영한 수정

- **수학:** 텍스트 추정값보다 원문 좌표로 확인한 선택지 분수를 우선한다. 원래 글리프가 남아 있는 단계에서 한 줄의 중첩 근호·분수·윗줄·지수를 함께 복원한다. 9번의 1/2·3/4, 12번의 `AC=2√14`와 `MH³+NH³`, 18번의 선분 관계식과 분수 부등식, 25번의 켤레복소수·두 `2n` 지수를 확인했다. 각도 기호의 PUA 매핑도 실제 PDF 렌더를 확인하고 추가했다.
- **수식 잘림:** 고정된 선택지 칸 높이를 실제 수식·줄바꿈 높이에 맞게 계산한다. 최종 시각 검사에서 확인한 분모·근호 잘림을 수정했고, 독립 높이 검사의 부족 건수가 19→0으로 줄었다.
- **영어·한국사:** 여러 조각으로 저장된 장식 테두리와 그 안의 실제 삽화를 구분한다. 지문은 원래 텍스트를 네이티브 문단·표에 넣는다. 말풍선 아래 실제 삽화는 남기고, 그 삽화에 포함된 하위 그림을 중복 출력하지 않는다. PDF 이미지의 잘린 표시 영역도 변환 행렬을 적용해 판별한다.
- **조판:** 합친 문단의 세로 좌표가 문단마다 0으로 돌아가 불필요한 페이지 전환을 만들던 문제를 수정했다. 줄 좌표를 단 안에서 누적한다. 영어 사례는 24쪽에서 12쪽으로 줄었으며, 본문을 지우거나 글자 크기를 줄인 결과가 아니다. `vertpos`의 누적 좌표 의미는 [rhwp의 필드 정의](https://github.com/edwardkim/rhwp/blob/main/mydocs/tech/document_ir_lineseg_standard.md)와 대조했다.
- **속도:** 시각 검수의 사각형 최대값 필터를 픽셀 결과가 같은 가로·세로 계산으로 교체했다. 텍스트 추출에서는 불필요한 이미지 인코딩을 제외하고, 분수 검사는 세로 좌표로 후보 글자를 좁혔다. 검사 페이지·해상도·판정 문턱은 줄이지 않았다.

## 재현 자료

최종 입력은 2026년 6월 고1 수학 12쪽·영어 8쪽·한국사 4쪽과 동일한 TXT다. 실제 desktop/web worker를 새 프로세스에서 실행한다. 업로드·다운로드, 외부 네트워크, 웹 브라우저 폴링 지연은 제외한다.

- `data/local_web_benchmark/20260909_final_fixes`: 5종 × 2경로 × 2회, 20/20 성공. 임의 객체 ID만 정규화한 10쌍의 패키지 내용 일치. 마지막 조판·수학 보완 이전의 속도 기록이다.
- `data/local_web_benchmark/20260909_verified`: 조판 보완 이후 반복 측정. 수학의 마지막 기호 보완 전후 코드가 섞일 수 있으므로 최신 결과는 다음 기록을 사용한다.
- `data/local_web_benchmark/20260909_release_check`: 마지막 수정 후 전체 경로 점검. 각 작업의 `source_stability.json`, 원본 해시, `timings.json`, `engine_report.json`, 패키지 비교를 보관한다.
- `data/local_web_benchmark/20260909_math_final`: 마지막 선택지 칸 높이 보완 후 수학 양 경로를 2회씩 재검사한다. 영어·한국사 경로는 이 변경을 사용하지 않는다.
- `data/local_web_benchmark/20260909_production_filter_parity`: 기존 수학 HWPX 12쪽의 모든 시각 지표·검토 플래그가 기존 기록과 정확히 일치했다. 동일 검수 단계는 145.66→10.99초(약 92.5% 단축)였다. 영어·한국사는 이전 API가 검수를 건너뛰어 대응 baseline 점수가 없으며, 이번에는 각각 8쪽·4쪽 전체를 계산했다.
- `scripts/fixtures/stacked_math_rows.json`: 재배포된 전체 시험지가 아닌, 해당 수식 오류를 재현하는 최소 글리프 좌표 조각이다.

## 검증 및 한계

`verify_conversion_quality_repairs.py`는 36회 수식 행 복원, 지문·삽화 보존, 누적 줄 좌표, 분수 선택지 5칸의 높이를 확인한다. `verify_native_pdf_editability.py`의 실제 분모 변조·본문 분할 크롭·허위 통계 거부 검사를 유지했다. `verify_pdf_math_pipeline.py`, `verify_conversion_integrity.py`, `verify_pdf_layout_export_api.py`도 통과했다. 필터는 64개 픽셀 입력과 3개 전체 점수 비교에서 기존 Pillow와 완전히 같았다. 전체 출력 34쪽을 렌더했고, 마지막 수학 선택지 높이 변경은 독립 높이 검사와 해당 페이지 렌더를 추가 확인했다.

네이티브 편집형 출력의 페이지 배치가 원본과 완전히 같다는 뜻은 아니다. 영어 8→12쪽, 한국사 4→10쪽처럼 재배치가 남아 있어 원본 시험지 그대로의 인쇄용 복원은 아직 부족하다. 본문 보존율은 원문 텍스트 조각의 패키지 포함 여부이며, 모든 수식·문장의 의미 정확도를 보장하는 비율이 아니다. 실제 한컴 GUI의 편집·재저장은 별도 검증이 필요하다.

기존 overlay 출력의 수학 약 190~264초와 현재 네이티브 출력의 전체 시간을 비교할 때는 출력 방식 변경까지 포함해야 한다. 필터 단독 효과는 같은 문서의 동일 페이지·동일 점수 비교로 판단한다. 이 작업의 정적 검사 범위에서는 새 코드가 통과했으며, `pdf_layout_writer.py` 전체 검사에는 기존 미사용 지역변수 4건이 남아 있다.
