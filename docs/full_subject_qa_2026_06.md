## 추가 정밀 진단

### 개인 수학 HWP: 단순 정규식 확장만으로는 부족한 이유

현재 `app/importers_hwp_ir.py`는 독립 문단 하나가 `[N점][시험명 NN]`인 형식만 수학 문항 경계로 인정한다. 개인 파일은 다음 순서를 사용한다.

1. 문제 본문 끝에 `[2점]`, `[3점]`, `[4점]`을 인라인 배치
2. 1~21번은 `➀➁➂➃➄` 선지 사용
3. 문제와 선지 뒤에 `[26년 06월 고1 전국 N번]` 배치
4. 바로 다음 문단에 `[출제의도] ...` 배치

현재 선지 상수는 `①②③④⑤` 계열만 포함하고 이 파일의 `➀➁➂➃➄`(`U+2780`~`U+2784`)는 포함하지 않는다. 실제 계수는 각 기호 21개씩, 총 105개로 1~21번의 5지선다 구조와 정확히 일치한다.

따라서 권장 구현은 마커 정규식 하나를 넓히는 수준이 아니라 `본문/선지 → 후행 출처 → 출제의도 → 다음 본문` 상태기계다. 가져오기 데이터에서도 `score`, `source_marker`, `intent`를 분리해 보존하고, 기존 writer 호환이 필요할 때만 `[점수][출처]` 표시 문자열을 조합하는 편이 안전하다.

### 국어 14쪽: 빈 페이지가 아니라 `[39~42]` 공유 지문

국어 PDF 14쪽은 텍스트가 없는 페이지가 아니다. 110개 텍스트 라인이 있고 첫 부분에 `[39~42] 다음 글을 읽고 물음에 답하시오.`가 있으나 실제 `39.` 문항은 15쪽에서 시작한다. 현재 segmenter는 번호 마커가 없는 페이지의 텍스트 블록을 보존하지 않고, pipeline이 전체 페이지를 번호 0 이미지 문항으로 대체한다.

이 페이지는 `markerless`가 아니라 `passage-only continuation`으로 분류해야 한다. `[39~42]` 범위를 파싱해 39~42번과 연결하고, 14쪽 텍스트를 편집 가능한 shared passage로 남기는 것이 정답이다.

## 우선순위

### P0

1. **완료** — 개인 수학 HWP의 후행 출처 마커·출제의도를 상태기계로 인식하고 `➀` 선지군을 지원한다.
2. **완료** — 복구된 30문항에 수식, 그림 3개, 문제 표 6개를 위치대로 연결하고 한글 라벨을 수식에서 분리한다.
3. **완료** — PDF 문항 마커에 figure bbox·글자 높이 억제를 적용해 한국사·통합과학 자료 숫자 과분할을 제거한다.
4. **완료** — 국어 14쪽을 번호 0 이미지가 아니라 `[39~42]` 편집 지문으로 39번에 연결한다.

### P1

1. 국어의 지문 범위 단위를 shared passage로 승격하고 45문항 inventory와 별도로 보고한다.
2. dedup key에 source/exam identity를 포함해 서로 다른 시험 간 오탐을 줄인다.
3. QA profile을 과목별 실제 문항 수로 분리한다: 국어/영어 45, 수학 30, 한국사 20, 통합사회/통합과학 25.
4. 비수학 과목의 특수기호가 native equation으로 분류되는 사례를 점검한다.
5. HWP IR 실패·레거시 폴백 사유와 객체 계수를 import notice에 노출한다.

### P2

1. 국어 HWP의 한컴바탕 11.48pt·150% 줄간격·표 중심 구조를 별도 school profile로 기록한다.
2. flow HWPX의 모든 페이지 contact sheet를 만들어 원본과 시각 비교한다.
3. `borderFillIDRef: 29` 같은 미등록 style reference는 원본 import와 분리된 템플릿 분석 호환성 항목으로 처리한다.

## 환경 주의

- 현재 OCR backend는 `NoOcrBackend`다. 이번 PDF는 born-digital이라 문항 번호와 본문이 대부분 복원됐지만, 스캔 시험지에는 같은 결과를 기대할 수 없다.
- E2E 하네스는 기존 baseline과 다른 명시 샘플을 넣으면 실제 변환 성공이어도 baseline mismatch로 종료코드 1을 반환한다. 전과목 임시 샘플용 `--no-baseline` 또는 별도 profile이 필요하다.
