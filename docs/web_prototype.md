# 웹 프로토타입 실행과 구현 범위

2026-09-07. [웹 서비스 기획](web_service_plan.md)의 첫 사용 흐름을 실제 변환 엔진에 연결한 **단일 PC용 프로토타입**이다. 외부 공개 배포나 비공개 베타 출시 관문 완료를 의미하지 않는다.

## 실행

```powershell
python -m pip install -r requirements.web.txt
python run_web_prototype.py
```

기본 주소는 `http://127.0.0.1:8788/`이다. 실행기가 브라우저를 열며, 최초 실행에는 한 번만 쓸 수 있는 초기 설정 링크가 포함된다. 표시 이름·이메일·비밀번호(10~128자)로 첫 계정을 만든다. 비밀번호는 해시로 저장하며 기본 계정이나 공용 비밀번호는 없다. 이메일 인증·비밀번호 찾기는 이 버전에 없다.

브라우저 자동 열기를 끄려면 `--no-browser`, 포트를 바꾸려면 `--port 8789`를 사용한다. 첫 계정 생성 전 초기 링크를 잃어버렸다면 실행기를 다시 시작해 새 링크를 받는다. 추가 시험 계정은 로컬 터미널에서 다음 명령으로 만든다.

```powershell
python run_web_prototype.py --create-user
```

서버를 종료하면 변환도 중단되지만 정상 종료 때 작업은 대기로 돌아가며 다음 실행에서 재개한다. 프로세스가 갑자기 종료된 경우 임대 만료 후 새 실행기가 한 번 재시도한다. 브라우저만 닫는 경우에는 서버가 계속 처리한다.

## 이번에 동작하는 것

- 첫 계정 설정, 로그인·로그아웃, 24시간 서버 세션, 로그인 시도 제한.
- 내 파일 업로드와 전체 내용 변환: PDF/HWP/HWPX/DOCX/TXT → HWPX/DOCX. PDF→HWPX는 기존 structured·전체 유형 보존 경로를 사용한다.
- 영속 작업 대기열, 상태 조회·필터·페이지네이션, 중복 접수 방지, 취소·다시 시도.
- 내 원본·결과 다운로드, 작업 상세의 문항 수·원본 쪽수·검수 안내, 삭제.
- 작업별 독립 엔진 DB·파일 경로. 이전 로컬 문제은행이나 공용 AI 설정을 웹에 노출하지 않는다.
- 20MB·PDF 50쪽 제한, 계정당 진행 작업 최대 3개, 전체 실행 1개·대기 20개, 최근 24시간 10회 접수 제한. 실패·취소는 횟수 집계에서 제외한다.
- 계정당 원본+최종 결과 500MB 보관 한도. 결과 게시 시에도 용량을 확인한다. 작업당 처리 제한은 20분이다.
- 작업 생성 후 30일이 지난 종료 작업의 자동 삭제. 원본과 결과를 함께 보관·삭제한다. 실행 중 작업은 정리하지 않는다.

파일·작업 접근은 매 요청마다 세션의 소유자를 확인한다. 전역 `/files`, 로컬 문제은행 API, AI 설정 API는 이 서버에서 제공하지 않는다. API 키는 변환 자식 프로세스에서 제거하며 PDF AI 인식도 명시적으로 끈다.

## 저장 및 운영 경계

기본 저장 위치는 `data/web_prototype/`이고 `HWP_WEB_DATA_DIR`로 바꿀 수 있다. 기존 `data/problems.sqlite3`와는 별개다. 별도 DB의 users/sessions/jobs가 로그인과 작업 상태를 담당한다. 각 작업 아래에 원본과 실행 시도별 결과가 저장된다.

SQLite는 이 프로토타입의 단일 호스트 검증용 선택이다. 기획의 PostgreSQL·OIDC, HTTPS 공개 배포, 백업/복구 운영, 컨테이너 Linux 호환·자원 제한, 작업 공정성 및 부하 시험은 후속 작업이다. 임시 압축 해제 데이터·과거 중단 시도는 최종 결과 용량과 별개이므로 운영 전 디스크 사용량 감시·정리 강화가 필요하다.

기획과 다른 임시 정책: 이 버전은 원본 7일/결과 30일 분리 대신 모두 30일 보관한다. 웹 문제은행 편집·스튜디오, 조직 공유, 관리자 화면, 스캔/OCR 정식 지원, 미리보기 이미지는 이번 버전에 포함하지 않았다. 기존 로컬 스튜디오는 기존 실행기로 이용한다. 실제 한글에서의 최종 편집·인쇄 품질을 보증하지 않는다.

## 검증

```powershell
python -m pytest scripts/verify_web_prototype.py -q
python scripts/verify_conversion_integrity.py
```

새 자동 검증은 격리 TEMP 데이터에서 두 계정의 접근 차단, 일회 설정·세션, CSRF/Host 검증, 중복 접수·한도, 잘못된 파일 정리, 동시 작업 선점, 과거 실행의 결과 게시 차단, 취소·시간 초과·재시작·만료 삭제를 확인한다. 실제 PDF→HWPX와 TXT→HWPX/DOCX 패키지 생성·다운로드도 검사한다.

브라우저 확인은 별도 시험 데이터와 `127.0.0.1:18788`에서 실행했다. 실제 PDF 선택→접수→새로고침 후 완료→작업 상세→다운로드 이벤트를 확인했다. 1536×1024 데스크톱과 390×844 모바일에서 검수했고 모바일 문서 가로 넘침은 0이다. [화면 시안](../assets/design/web-prototype-concept.png)의 업로드/안내 2열, 초록색 액션, 제목 계층, 작업 목록, 문서 아이콘을 비교하고 안내 영역 높이와 갱신 중 버튼 유지 문제를 수정했다. 보관 한도 안내와 실제 결과 행은 구현 기능을 반영한 추가 요소다. 전체 페이지 캡처는 인앱 브라우저의 배율·합성 문제가 있어 최종 증거는 기본 화면 캡처를 사용했다.

## 버그 신고

로그인 후 상단 **버그 신고** 또는 작업 상세의 **이 작업 신고**에서 제목·증상·재현 방법·기대한 결과를 입력한다. 접수 번호가 발급되고 **내 신고**에서 최근 50개 신고와 처리 답변을 확인할 수 있다. 사용자별 하루 20건으로 제한하며, 같은 요청 재전송은 중복 등록하지 않는다.

앱 버전·브라우저·화면 크기와, 연결한 작업의 ID·형식·신고 당시 상태·오류만 진단 정보로 저장한다. 원본 파일이나 문서 본문, 세션·API 키, 로컬 파일 경로는 자동 첨부하지 않는다. 신고자가 입력한 본문은 그대로 보관하므로 비밀번호 등은 적지 않는다. 작업을 삭제해도 신고 및 신고 당시 진단 정보는 유지된다. 외부 메일·GitHub·메신저 전송은 없다.

운영자는 서버를 실행한 같은 PC와 데이터 경로에서 다음 명령으로 처리한다. 웹 사용자가 타인의 신고를 보거나 상태를 수정하는 API는 제공하지 않는다.

```powershell
python scripts/manage_bug_reports.py list --status submitted
python scripts/manage_bug_reports.py show BUG-접수번호
python scripts/manage_bug_reports.py update BUG-접수번호 --status investigating --reply "재현하여 확인 중입니다."
python scripts/manage_bug_reports.py update BUG-접수번호 --status resolved --reply "수식 배치 오류를 수정했습니다. 다시 변환해 주세요."
```

`submitted`는 접수됨, `investigating`은 확인 중, `resolved`는 처리 완료다. 답변은 신고자가 **내 신고 → 새로고침** 후 확인한다. 상태 변경은 운영자의 수동 처리이며 신고 즉시 자동 수정되거나 운영자에게 외부 알림이 발송되는 기능은 아니다.

신고는 `bug_reports` 테이블에 저장한다. 추가 검증은 소유권·접근 제어, 요청 재전송·입력 제한·접수 한도, 작업 삭제 뒤 진단 보존, 운영자 답변과 재시작 후 보존을 포함한다.

## 코드 위치

- `app/web_main.py`: 별도 웹 앱, 인증·업로드·작업·다운로드·신고 API.
- `app/web_store.py`: 계정·세션·SQLite 큐·신고 저장과 소유권 검사.
- `app/web_worker.py`: 실행 감독, 취소·시간 제한·결과 게시·정리.
- `app/web_convert.py`: 격리 프로세스에서 기존 변환 엔진 호출.
- `static/web/`: 로그인, 업로드, 작업 목록·상세 화면.
- `static/web/bugs.js`: 버그 신고 작성·접수 내역·답변 화면.
- `scripts/manage_bug_reports.py`: 운영자용 신고 조회·상태·답변 관리.
- `run_web_prototype.py`: 로컬 실행 및 계정 생성.
