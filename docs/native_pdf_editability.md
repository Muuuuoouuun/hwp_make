# PDF 편집성 검증 기준

2026-09-23 최신 검증: [격자 안내문 문단 편집과 엄격 재평가](audits/2026-09-23/grid-frame-paragraphs-progress.md). 36쪽 엄격 배치 평균은 같은 환경 기준 **87.04 → 87.06**, 최저 **72.85**이며 **93점 미달**입니다. 전체 회귀는 **103 통과·11 생략·1 실패**입니다. 영어 27번 격자 안내문의 글머리표 5개를 독립 편집 문단으로 복원하고 수정·재저장을 확인했습니다. [이전 그래프 표기 감사](audits/2026-09-23/native-graph-annotations-progress.md)의 점 이름·수식 편집과 한 문단 장문 편집 검증은 별도로 유지됩니다. 영어 25번 그래프 라벨 배치, 실제 한컴 GUI 편집, 렌더 재현성은 미해결입니다. 문자 대응률은 중복·의미·읽기 순서의 완전성을 보증하지 않습니다.

## 출력 계약

- 문항마다 하나의 실제 HWPX 글상자(`hp:rect/hp:drawText`)를 만듭니다. 각 글상자는 인라인 개체이며 내부에 해당 문항의 문단·표·수식·그림을 함께 담습니다. 문항 전체를 한 개체로 선택·이동할 수 있는 구조입니다.
- 글상자 안의 텍스트는 의미 문단으로 이어집니다. 렌더용 줄바꿈 캐시는 같은 문단 안에 저장하며, 줄마다 별도 글상자나 문단을 만들지 않습니다. 원본 보기 상자와 데이터 표도 글상자 내부의 실제 표입니다.
- 원본 장식 프레임을 실제 격자가 나누는 경우, 원문 줄 좌표를 확인해 각 텍스트 조각의 문단을 복원합니다. 글머리표는 각각 편집 가능한 문단으로 두고 일반 줄바꿈은 합칩니다. 격자가 없는 장식 프레임에는 이 규칙을 임의로 적용하지 않습니다.
- 원본의 독립된 그래프 주석은 원본 비트맵과 함께 문항 안의 실제 그리기 그룹에 담을 수 있습니다. 점 이름·함수식은 개별 편집 개체이며, 본문 문장을 분절하는 용도로 쓰지 않습니다. 현재 복원은 원본 비트맵 소속·축·점·함수 표기를 확인할 수 있는 일부 그래프에 한정합니다.
- 원본의 작품 출처·짧은 행의 정렬·행간·연 사이 간격으로 확인된 운문은 연 하나를 실제 문단 하나로 묶습니다. 시의 의도적인 행 구분만 문단 내부 네이티브 줄바꿈으로 저장합니다. 일반 산문의 인쇄 줄을 강제 줄바꿈으로 고정하지 않습니다. 현재 이 복원은 전체 원문이 대응하고 문자 스타일이 동일한 공통 지문 단일 셀 틀에 한정됩니다.
- 본문·수식 이미지 덮개, 전체 페이지 이미지, 문장·줄을 개별 좌표 개체로 분해하는 방식은 사용하지 않습니다. `coordinate` 요청과 옛 `high_fidelity_math=True`도 이미지 덮개를 복구할 수 없습니다.
- 문항 그룹은 원본 인식 목록의 번호·페이지·개수와 대조합니다. 번호가 재시작하는 시험 변형은 별도 ID를 사용합니다. 공동지문과 마지막 확인사항은 문항 밖의 별도 그룹으로 유지합니다.
- 숫자 분수는 네이티브 수식입니다. 한글 문구 분수는 본문 글꼴을 쓰는 위아래 셀과 분수선으로 만듭니다. 표 안의 한글 분수가 중첩 표를 만들어 실제 렌더에서 사라지는 경우는 아직 지원하지 않으며 결과물을 차단합니다. 25수능 화학 19번에서 이 제한이 재현됩니다.
- 인식 결과에서 빠졌던 보기·표 내용도 PDF 본문의 실제 텍스트와 좌표에서 복구합니다. 과학은 과탐 템플릿을 사용합니다.
- 보기·표 셀에서도 원본의 물리적 줄바꿈을 의미 문단으로 결합합니다. ㄱ/ㄴ/ㄷ 항목과 실제 문단 경계는 유지하고, 높은 분수 뒤의 문장 끝도 같은 문단에 남깁니다.
- 원본 글꼴·글자 크기·한글 자간·행간·단 폭을 측정해 실제 문자/문단 스타일과 줄 캐시에 적용합니다. 이번 자료의 본문은 원본 A3에서 주로 11.209pt, 행간 16.6~16.7pt, 자간 약 -5.4%이며 A4 비율로 환산합니다.
- 첫 페이지 머리말 높이를 양쪽 단에서 제외하고, 실제 표 내용 높이로 셀을 맞춘 뒤 원본 페이지·단 경계에 맞춰 배분합니다. 나란한 원본 그림은 독립 인라인 그림들로 같은 문단에 놓습니다.
- 원본에서 그림 옆과 아래로 이어지는 본문은 하나의 문단과 실제 문단 고정 그림의 둘러싸기로 만듭니다. 단 안의 그림 위치·본문 줄 영역·원본 텍스트 대응이 확인되는 경우에 적용하며, 편집 후 그림을 피해서 줄 폭을 다시 계산합니다. 그림의 원본 좌표와 표시 크기·확대 비율을 구분하여 축소한 그림이 잘리지 않도록 합니다.

## 생성기 점수와 분리한 검증

`app/pdf_editability.py`는 실제 출력 ZIP/XML과 원본 PDF를 읽습니다. 생성기가 보고한 텍스트 보존율이나 이미지 개수만으로 통과시키지 않습니다.

1. `app/pdf_question_inspection.py`와 함께 실제 문항 글상자의 개수·순서·번호, 인라인 위치, 내부 편집 가능 문단·표·수식·이미지를 검사합니다. 임의 글상자나 한 문항을 여러 글상자로 쪼갠 결과는 허용하지 않습니다. 각 문항의 원문도 해당 글상자 안에 있어야 합니다. 렌더러가 넘친 내용을 보여 주더라도 실제 문단·개체 높이보다 작은 글상자는 거부합니다.
2. 이미지 바이트와 출처 영역을 대조할 뿐 아니라 원본 PDF를 독립적으로 다시 렌더링해 실제 픽셀을 검증합니다. 생성기가 그림과 SHA-256을 함께 바꿔도 통과하지 못합니다. 별도 원본 비트맵 목록으로 표 안의 그림 누락도 검사합니다. 본문이 얹힌 종이 테두리는 원본 잔여 잉크가 실제 테두리뿐이고 같은 원문을 가진 네이티브 테두리표가 있을 때만 재구성으로 인정합니다. 벡터 도형 전체의 완전성 증명은 별도 과제입니다.
3. 모든 이미지 영역의 합집합과 원본 본문 글자 좌표를 비교합니다. 작은 크롭 여러 개로 본문을 덮어도 거부합니다.
4. 원본 본문 텍스트 조각 보존율 98% 이상을 요구합니다. 실제 본문·문항별 대조와 생성 통계에서 머리말·꼬리말 제어의 텍스트와 수식은 제외하고, 같은 문단 앞뒤의 본문 run·텍스트 제어 뒤 tail은 이어 읽습니다. 본문을 지우고 머리말이나 꼬리말로 옮긴 변조는 별도 전체 본문·문항별 대조와 두 API 모드에서 거부합니다. 실제 머리말의 존재·표시는 별도로 검사합니다. 이 지표는 텍스트 조각 대조이며 중복·의미·순서의 완전한 정확성을 보증하지 않습니다.
5. 원본의 복원 가능한 적층 분수를 다시 조사하고, 출력 수식 또는 실제 분수 표의 분자·분모와 개수를 대조합니다. 수식 개수가 같아도 분모가 달라지면 실패합니다.
6. 편집성 위반은 HTTP 422로 거부하고 해당 실행의 결과물을 정리합니다. 렌더 비교는 생략하지 않습니다. 편집성 통과와 원본 배치 품질 통과를 별도로 기록합니다.
7. `app/pdf_question_rendering.py`는 글상자 내부의 실제 SVG 텍스트 출력과 색·불투명도·표시 여부·변환·사각형 클립 범위를 확인합니다. 흰색으로 숨긴 글자, 렌더에서 빠진 텍스트 조각, 처리하지 못하는 중첩 표를 발견하면 HTTP 422로 거부합니다. 이 검사가 모든 글자·수식의 모양 일치를 증명하지는 않으므로 전체 페이지 시각 검토도 병행합니다. 수식 존재만으로 수식 외관 검증을 통과했다고 표시하지 않습니다.
8. `app/pdf_script_attachments.py`는 생성기의 복구 결과를 기대값으로 사용하지 않고 원본 글자의 크기·기준선·수평 간격에서 위·아래첨자 연결을 추출합니다. `10¹⁵`를 `1015`로 바꾸거나 `T₁`을 `T¹`로 바꾸면 문자 개수가 같아도 실패합니다. 문항별 수식도 따로 대조해 다른 문항의 올바른 첨자로 누락을 대신할 수 없습니다.
9. `app/pdf_source_semantics.py`는 원본 수식의 수치·연산자와 실제 표의 행·열 주소를 대조합니다. `1500m/s→9999m/s` 변경과 수온·염분 셀 교환은 문자 보존율과 별개로 거부합니다. 복합 분수 일부는 아직 독립 검증기의 지원 범위 밖이라 차단될 수 있습니다.
10. `app/pdf_paragraph_flow.py`는 원본 PDF에서 같은 문단의 이어지는 줄로 판단할 수 있는 연속 본문 줄을 찾고, 실제 HWPX의 동일한 `hp:p` 안에 순서대로 존재하는지 검사합니다. 생성기의 문단 표식이나 줄 캐시 개수만으로 통과시키지 않습니다. 줄별 문단 분리, 강제 줄바꿈으로 만든 겉보기 문단, 유효 범위를 벗어난 줄 캐시는 실패입니다. 짧은 시·목록·그림 옆 줄처럼 판단 근거가 부족한 경우는 문단 연결을 단정하지 않으며, 혼합 수식은 한글 본문 연결과 독립 수식 의미 검사를 함께 적용합니다. 이 검사도 공개 API의 편집성 관문에 포함합니다.
11. `app/pdf_floating_geometry.py`는 문단 고정 그림의 위치·본문 연결·단 범위·줄 영역 비겹침을 검사합니다. 비인라인이라는 이유만으로 임의 그림을 허용하지 않습니다. `app/pdf_picture_geometry.py`는 내장 비트맵의 실제 픽셀 크기와 출력 자르기 범위를 대조하며, 실제 렌더 검사는 모든 네이티브 그림의 완전한 표시를 요구합니다. 일부만 잘리거나 숨긴 그림은 원본 바이트가 남아 있어도 실패합니다. 왼쪽/오른쪽 그림과 문항/공통 지문의 실제 PDF 변환·편집·재저장을 별도 회귀로 검사합니다.
12. 같은 검증기는 PDF 원본 스팬의 줄 끝 공백도 따로 읽습니다. 같은 글꼴의 긴 한글 줄에서 끝 공백을 반복 확인할 수 있는 경우, 이어지는 한글 단어 사이에 공백이 추가되거나 원래 공백이 삭제되면 실패입니다. `극히→극 히`는 공백을 제거한 문자 보존율이 같아도 거부합니다. 모든 줄 끝 공백이 이미 사라진 PDF와 판단 근거가 없는 줄에서는 단어 경계를 추측하지 않습니다.
13. 문단 들여쓰기·내어쓰기는 저장된 문단 속성과 수정 전후 실제 줄 시작 위치로 검사합니다. 문항 밖 공통 지문도 실제 단 너비 안에서 조판되어야 합니다. 문단·글상자 수와 원본 그림을 유지하고, 재저장한 XML이 안정적인지도 확인합니다. 선택지 탭은 속성 보존과 실제 표시 위치를 따로 검사하며, 현재 위치 오차 회귀는 7.89px에서 0.1114px로 줄어 기존 6px 기준을 통과합니다. 원본 탭 위치를 유지하고 실제 출력 글자·수식 폭으로 저장 간격을 갱신하며, 문단 편집·자동 줄바꿈·재저장을 다시 검사합니다.
14. 수식 혼합 문단도 한 문단으로 유지합니다. 전체 수식의 원본 조각 대응, UTF-16 줄 시작 위치, 수식을 가로지르는 잘못된 줄 경계, 괄호·연산자 불일치를 검사합니다. 본문 기준선은 실제 본문 글꼴 스팬을 우선 사용하고 큰 수식이 있는 첫 줄도 원본 기준선을 유지하도록 구역의 위쪽 공간을 확보합니다. 수학 2~12쪽 양쪽 단의 첫 문항 22개 세로 기준선 최대 오차는 0.003541px로 0.1px 기준을 통과합니다. 같은 검사에서 가로 오차는 별도로 기록하며 9쪽 22번 +0.4449px는 실패입니다. 문단 사이 여백·글상자 높이·수정 후 성장은 따로 검사합니다. 일반 대체 머리말의 첫 쪽 4.081255px 오차와 원본 글꼴·수식 간격 문제는 남아 있습니다.
15. 측정한 첫 쪽 머리말은 본문과 별개의 실제 구역 머리말이며, 내부 텍스트는 편집 가능한 문단입니다. 제목·영역명·교시·쪽 번호의 시작점·기준선, 구역 전환 후 제목의 중복 상속 방지, 뒤쪽 본문 좌표 불변, 제목 편집·재저장을 검사합니다. 세 과목 12개 항목의 최대 위치 오차는 0.0152px지만 글꼴 굵기와 장식 테두리 등은 여전히 시각 검토가 필요합니다.
16. 공통 지문 표 안의 텍스트도 실제 한 문단에서 편집되어야 합니다. 원본 전체 줄과 셀 문단의 순서·내용 대응, 원본 줄 간격·문단 간격·들여쓰기, 표 높이에 문단 여백이 포함되는지, 공개 setter 이후 표 성장·뒤 문단 비겹침·재저장을 검사합니다. 초기 줄 캐시만으로 시의 의도적인 행·연이 수정 후에도 유지된다고 판정하지 않습니다.
